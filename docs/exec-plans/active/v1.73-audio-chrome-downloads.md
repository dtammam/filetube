# v1.73.0 - the audio-chrome + Downloads-library wave

Spec for the two-reviewer gate; the follow-up wave Dean ruled the
morning after v1.72.0 shipped and device-passed. This file carries the
rulings verbatim - it is the compaction-proof handoff: if the session
dies, a fresh agent builds from HERE, never from conversation memory.

## The architectural ruling (Dean's question, my framing, his "yep")

Dean asked whether multiple player views are harming us. The framing
that matches the code: there is ONE player engine (public/js/player.js
- one media host, one dock, one survives-navigation state machine).
What forked is the AUDIO CHROME: podcasts got the big-art now-playing
view in v1.71, music kept a plainer full mount, and affordances
(Prev/Next) drifted. This wave consolidates the AUDIO chrome into one
shared component with two mounts. The video watch chrome is explicitly
OUT OF SCOPE - Dean rates it perfect; do not touch it.

## Dean's rulings (2026-08-03 morning, all "agree")

1. ONE merged "Continue listening" home row: music tracks + podcast
   episodes interleaved by recency (progress updatedAt desc), capped
   at 8. ONE Settings toggle governs it (ft-home-continue-listening);
   the separate podcasts toggle retires from the Settings UI, and a
   device where EITHER old toggle was on shows the merged row (on is
   the default anyway; only both-off stays off).
2. Music gets the podcasts now-playing chrome, SHARED not copied:
   extract the expanded big-art view into one component consumed by
   /podcasts and /music; dock tap on a track opens /music?nowplaying=1
   and expands it (the podcasts ?nowplaying=1 contract exactly).
3. Home rows cap at 8 - ALL of them (watching, merged listening,
   reading) for a uniform home.
4. The ytdlp library gets a video-platform glyph: rounded rectangle +
   play triangle (evokes YouTube, clones no trademark), added to the
   icon pipeline in all four sets (emoji set uses a TV/play emoji).
5. The ytdlp library is promoted to a "hard" Library entry:
   - Label: "Downloads" (Dean: "default as Downloads is fine").
   - Sidebar: FIRST in the Library section, above Music/Books/
     Podcasts/History, using the new glyph; content-gated injection
     (the module-health posture every other entry uses).
   - Destination: the existing synthetic-folder grid (/?root=<ytdlp
     download dir>) - zero new surface.
   - Bottom bar: a new optional item, DEFAULT-HIDDEN ("I like it
     being customizable still") - joins BOTTOM_NAV_OPTIONAL +
     BOTTOM_NAV_DEFAULT_HIDDEN + all nine shells + the editor labels.
6. BUG (Dean's device find, ruled in): video playing + podcast/track
   queued + watch-page NEXT button = "Failed to Load Media". The
   manual Next/Prev queue path is a legacy arm that hand-builds
   /watch.html?v=<id> instead of riding queueEntryHref - exactly the
   "guarded legacy fallback arms" the cap-3 definition flags. Fix:
   the button path routes through queueEntryHref (kind-dispatched),
   with source locks. Prev/Next affordances for music/podcasts land
   on the shared now-playing chrome (queue-aware FIRST - the queue
   owns up-next - falling back to the kind's own context: show order
   / album order). FULL VIEW ONLY - the dock stays minimal; the lock
   screen already has Media Session.
7. Podcast push notifications: an episode finishing its download
   creates a notification + web push, tappable to /podcasts?play=
   <episodeId>. The notifications feed is media-id-keyed, so the kind
   must be CARRIED: schema v13 adds a kind column ('media' default |
   'podcast') - APPEND-ONLY migration, its own block (the v1.72
   lesson is LAW now). Episode notification rows retire with the
   episode purge carrier; bell rows render kind-aware (show art, the
   podcasts deep link); pushes ride the SAME global notifications
   toggle as downloads (one switch - disclosed, not a new setting).
8. Housekeeping: v1.70/v1.71/v1.72 device passes recorded as PASSED
   (informal, "working excellently"); tech-debt #96-#99 stay parked.
9. (added mid-intake) The audio-art view's SIDE-FILL treatment goes:
   when a square cover renders in the now-playing/audio player (seen
   on Podcasts), a stretched rectangle version of the SAME image
   currently fills both sides of the letterbox. Dean: "It's not
   good. Let's make that not happen." Square art renders clean -
   whatever mechanism paints the echo (a cover-fit background-image
   behind an object-fit:contain img, or equivalent) is removed for
   the audio mounts; a plain themed backdrop takes its place. Lands
   inside T3 (it is the same chrome being consolidated).
