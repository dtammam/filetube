# v1.99.0 - Shimmer sweep tranche 2 + the standing reveal-once contract

Status: ACTIVE. Branch `release/v1.99.0`. Second FOUC-sweep tranche (audit:
`docs/exec-plans/active/fouc-shimmer-audit.md`).

## Scope (Dean: "proceed" + "include it in CONTRIBUTING so any new thing does this")

1. **The standing CONTRACT (CONTRIBUTING).** A new MANDATORY convention beside the
   design-token rules: every surface that renders from data fetched AFTER first
   paint MUST ship a reserved-space skeleton-shimmer that reveals ONCE (seed
   before the await; the real `innerHTML=` on resolve is the reveal; clear on
   error; zero-shift by reusing the real box). "Blank-then-pop / a bare spinner /
   a reflow-as-data-lands" is a review finding, like an ungoverned literal is.

2. **Avatar-bar flicker (Dean's device report on v1.98).** The top chip-row "flow"
   flickers / gains-or-loses a row: root cause is the MOBILE avatar bar
   (`#modern-avatar-bar`, main.js:1351) that ships `hidden`, then `/api/channels`
   resolves and it POPS IN above the chips, shifting them down (variable
   recent-uploader count = the "more or less"). FIX: persist the last-known
   channel count in localStorage; on load, if >0, seed the strip with N shimmer
   avatar chips + un-hide it (reserve the space), and populateModernAvatarBar
   reveals the real chips (or collapses if now truly none) - the v1.53
   capability-cache / seed-from-last-known pattern. First-ever load has no cache
   (one-time pop-in, disclosed).

3. **Watch RELATED rail** (audit row 15). `loadRelatedFiles` fetches
   `/api/videos` then fills `#related-files-container` - blank rail until resolve.
   FIX: seed `.related-card`-shaped skeleton rows + reveal the header before the
   fetch; the existing `innerHTML=` (real cards / "No other files" / error) is the
   reveal. (`.related-thumb` is `#000` letterbox - restore `--bg-secondary` on the
   skeleton variant, the v1.98 art-box pattern.)
