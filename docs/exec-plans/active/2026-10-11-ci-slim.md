# CI slim: the same protection, run once instead of twelve times

No app change and no version of its own: it ships as a PR on top of v1.383.0 (close-out: "Shipped on top of v1.383.0", like the
art-version-flake plan). Norms: no em dashes; stage by name; `git commit -F <file>`; never pipe a commit or push; fnm Node PATH
before any node/npm/git command; never `--no-verify`; never self-merge.

## 1. Measurement (Root, 2026-10-11, from gh run timings of v1.382.0 / v1.383.0)

- Suite: 928 files, ~11.8k tests (unit ~9.16k / 649 files, integration ~2.63k / 279 files); one full CI job ~9-10 min (lint + npm ci
  + suite) on a 4-core runner. Not overtuned; the low bug rate says it pays. NO test is to be deleted by this plan.
- Per release: PR = ci (22) + ci (24) + Visual 12 jobs (~137 runner-min); tag push = Publish qualify (22) + (24) (~22); push to main
  after merge = ci (22) + (24) again + Visual 12 again + Publish edge qualify (22) + (24) again (~157). About 315 runner-min, the full
  suite 8 times in CI on essentially one tree, Visual twice. Locally on top: pre-commit runs all ~9.16k unit tests on EVERY commit,
  pre-push the full suite, builders the full suite on BOTH Nodes twice per release.
- A release starts ~20 jobs at once (PR 4 + Visual 12 + tag 5) = the free-plan concurrency limit: the measured cause of the "jobs
  starve, cancelled ~15 min" scar in the Root's memory.
- Node 24: production is `node:22-alpine`; the whole git history has NO Node-24-only failure (every mention is "both passed"). 24 is
  insurance for the upgrade before Node 22's end of life (April 2027).

### W4 - R4 (sharding)
- ci.yml `ci` job: matrix `{node: 22, shard: 1..4}` + `{node: 24, shard: 0}` (0 = whole suite) or an equivalent include list; lint
  and lint:ui run ONCE (a separate small job or only on shard 1), not in every shard. The suite command per shard:
  `node --require ./test/helpers/tmp-cleanup.js --test --test-shard=<i>/4 test/*/*.test.js`. Prove the 4 shards together run every
  file exactly once (count files / tests per shard vs the unsharded run) and paste the numbers. Per-shard test-output artifacts keep

- Branch protection: required check names change (ci (22) -> ci (22, 1) ...). List the old and new required checks for Dean and ask

### W5 - R5 (Visual reuse) - the hard one; stop rule applies
- Read .github/workflows/visual.yml end to end (visual, visual-comment, refresh-source, rebaseline, baseline-refresh,
  rebaseline-merge) and test/unit/visual-workflow.test.js first; write a short "how it works today" note in this plan.
- Goal: on a push to main from a merged PR, `baseline-refresh` uses the merged PR's `visual-shots-*` artifacts (same tree: the PR ran
  on the merge result) instead of the 12-job retake; the 12-job `visual` matrix does NOT run on that push. Fallback: when the PR's
  artifacts cannot be found or are older than the merge commit's tree (main moved between the PR run and the merge), run today's
  retake. A push to main that is not a merged PR (a direct push, the bot's own baseline-refresh merge) keeps today's behaviour or skips,
  as today.
- Prove it on a throwaway branch / workflow_dispatch before relying on it; the visual-workflow census pins the new shape.
- If it cannot be made safe in this release, ship the rest and put W5 on the ROADMAP with what you learned.

**Builder finding (2026-10-11): W5 is already built; no change.** visual.yml already has the reuse path: `visual` is
`if: pull_request` only (the 12-leg matrix never runs on the main push); `refresh-source` finds the merged PR's passing
`visual` run when main-before-merge is an ancestor of the PR head and the merge commit's tree equals the head's tree, and only
accepts it with all 12 `visual-shots-*` artifacts unexpired and a same-repo head; `baseline-refresh` downloads those shots;
`rebaseline` (the 12-job retake) runs only when `refresh-source` returns no run. The census (visual-workflow.test.js) pins it.
Proof from real runs: the v1.383.0 merge (run 38112067250) ran refresh-source 15 s + baseline-refresh 24 s with `rebaseline`
skipped; the v1.382.0 merge (run 38034879017, before the reuse path) retook all 12 legs. The Root's section 1 count of "Visual
twice" was from the older runs. Nothing to ship for R5.
