# v1.98.0 - Shimmer sweep, tranche 1: the library views

Status: ACTIVE. Branch `release/v1.98.0`. First tranche of the FOUC/shimmer sweep
(full audit: `docs/exec-plans/active/fouc-shimmer-audit.md`).

## Problem (Dean)

"Any loading moment without shimmer is the defect." Four whole primary places -
Music, Podcasts, Books, History - paint an EMPTY host and then snap the entire
grid/list in when the fetch resolves (blank-then-pop). This is the single most
common "not a modern app" moment. The reveal toolkit already exists
(`.skeleton-shimmer`, `buildSkeletonGrid`); this tranche makes it the rule for
these four landing views.

Audit rows: 19 (Music `music.js:491-530`), 22 (Podcasts `podcasts.js:126-138`),
26 (Books `books.js:127`), 35 (History `history.js:157-158`).

## Approach - the proven buildSkeletonGrid recipe, per view

Seed a SHAPE-MATCHED skeleton into each view's host BEFORE its first fetch; the
existing `host.innerHTML = <real markup>` on data-resolve is the ONE reveal (no
new reveal plumbing). Each skeleton reuses the view's REAL container + aspect
box class (which already reserves space via `aspect-ratio`), so the swap is
zero-shift (lesson #7 - the browser measures the real box, no CSS-var guessing):

- **Books** (`#books-grid`, grid): `.book-card` skeleton - `.book-cover-link`
  (aspect 2/3, style.css:8111) shimmered + two skeleton lines. Seed in `loadBooks`
  before the `/api/books` fetch. NOTE: the Continue-reading shelf (row 27) +
  chips (row 28) are a SEPARATE structural item - NOT in this tranche.
- **Music** (`#music-content`, default = album grid): `.music-card-grid` of
  `.music-album-card` skeletons - `.music-album-art` (aspect 1/1, :8990) shimmered
  + lines. Seed in `render()` before the fetch. (Songs/drill/artist sub-states
  reveal fast from the same fetch; the album landing is the common blank moment.)
- **Podcasts** (`#podcasts-content`, default = shows grid): `.podcast-grid` of
  `.podcast-card` skeletons - `.podcast-card-art` (aspect 1, :10529) shimmered +
  lines. Seed before the shows fetch.
- **History** (`#history-list`, list): `.history-row` skeletons - `.history-thumb`
  (aspect 16/9, :10355) shimmered + info lines (no remove button in the skeleton).
  Seed before `fetchPage(0, true)`.

Each skeleton builder is a pure function (testable like `buildSkeletonGrid`); the
real markup `innerHTML=` replaces it on resolve; the empty-state / error paths
already `innerHTML=` real content or the empty message, so no skeleton is ever
stranded (verify each view's catch + empty branch).

A shared count constant (~8 for grids, ~6 for the history list). Skeleton CSS
reuses `.skeleton-shimmer` + `.skeleton-line*`; add per-view skeleton rules ONLY
where a reused class needs the shimmer fill to show (e.g. a shimmered aspect box
that is normally an `<img>`).

## Tests (predictions)

- Each `build*SkeletonCards/Rows(n)` returns exactly n shimmer nodes, n<=0 -> ''
  (the buildSkeletonGrid contract), reusing the real container/aspect class +
  `.skeleton-shimmer`.
- Each view seeds its skeleton into the host BEFORE the first fetch await
  (source-order / jsdom: the host is non-empty and shimmering before resolve),
  and the reveal replaces it (no skeleton node after data lands).
- Reduced-motion + census/ledger unaffected (reuse tokens).

## Adversarial attack surfaces (brief)

- Prove a skeleton is STRANDED (never revealed) on an empty result, an error/
  catch, a fast-cached resolve, or an aborted view (SPA nav mid-fetch).
- Prove the reveal SHIFTS layout (skeleton box != real card box) on some view.
- Prove a seeded skeleton leaks into a NON-landing sub-state (e.g. music drill,
  podcast episodes) or double-seeds on re-render.
