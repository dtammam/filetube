## Survey (verified in-tree)

Activity producers ALL already stamp a kind + counters + `current` into
`activity.oneShots` (GET /api/subscriptions/status):
- `repull` (batch reheat, index.js:1082) - total/done/skipped/failed/
  moved/moveFailed/attributionConflicts, current label
- `repull-item` (flame button, index.js:1340) - total:1, current, mediaId
- `refresh-avatars` (index.js:1660) - total/done/skipped/failed, current
- `attribute-bulk` (server.js:11730) - total/done/moved/collisions/
  alreadyThere/failed
- real one-shots: per-job UUID entries, `title`/`label`, no kind
- subscriptions namespace: separate, already named by channel (v1.24.8)

The CLIENT (`buildDownloadChipItem`, common.js ~7079) ignores `kind` for
one-shot-namespace entries: `title || label || 'One-off download'` - so
every batch job renders as "One-off download". That is Dean's ask 1,
whole and entire. The aggregate line counts everything as downloads.

Status-text treatments found (the incohesion): bare `.sub-repull-status`
spans x3 (subscriptions header); inline-styled `<small>` (oneshot
section); BOLD inline-styled spans `scan-status`/`book-scan-status`/
`music-scan-status`/`automation-scan-status` (setup); `logo-status` as
`.sub-row-meta`; `.oneoff-modal-status` div (watch modal).
(CORRECTION during implementation: the survey also claimed
`restore-status` rendered success text in `.field-error` red - false;
every one of its writes is an error, so it deliberately keeps
`.field-error`.) Buttons: `btn` /
`btn-primary` / `btn-sm` mixed in one row; inline padding/font-size
overrides on Save buttons; hidden Cancel buttons that pop INTO the row.

## Track A - chip activity vocabulary (ask 1)

- `buildDownloadChipItem` learns the kinds. Name line per kind:
  - `repull`: "Reheating library"
  - `repull-item`: "Reheating video" (current title when present)
  - `refresh-avatars`: "Refreshing avatars"
  - `attribute-bulk`: "Attributing videos"
  - one-shots keep `title || label || 'One-off download'` (only genuine
    downloads remain on that fallback).
- Status line reuses the existing `formatOneOffStatusText` shape where
  counters exist: "N of M" + current item; kind-specific tails (moved/
  collisions for attribute-bulk; skipped for reheat) only where already
  carried - no new server fields.
- Aggregate/summary line stops calling batch jobs downloads: activity
  entries count as "active" ("2 active - 1 queued"); pure-download
  wording kept when only downloads are present (no regression for the
  common case).
- Server: NO changes (all kinds verified present). Client-pure track.

## Track B - action-bar + button normalization (ask 2)

- New `.action-bar` CSS component: equal-width buttons via grid
  `repeat(auto-fit, minmax(<token>, 1fr))`, era-token borders/radius,
  one gap token, uniform height (existing `--fs-*` sizes; NO new inline
  styles). Cancel buttons swap IN PLACE of their trigger (same grid
  cell, `hidden` toggling both ways) - no row reflow.
- Applied to: subscriptions header actions (4 buttons + 2 cancels);
  setup Save & Scan / Scan now / Scan books / Scan music / Save rows;
  setup logo upload/remove pairs; stats "Show keyboard shortcuts"
  (single button, same component for consistency); one-off SECTION's
  Download button row (subscriptions page).
  (SCOPE TRIM, gate round 1 QA S2, deliberate: the backup
  Download/Restore controls were listed here but are NOT one row - they
  are two separate flows in separate form groups, each with its own
  explanatory text and, for Restore, its own file input + error line.
  Forcing them onto one action-bar would imply a pairing that does not
  exist. Left as-is.)
  (SCOPE TRIM 2, gate round 1 adversarial W5: the one-off SECTION's
  Download button on the subscriptions page stays inline in its field
  row - it sits at the end of the URL/format/quality inputs exactly like
  the add-subscription button above it, and pulling one button out of a
  field row into a bar would unify it with nothing. The logo
  upload/remove pairs, also flagged by W5, WERE implemented.)
  (Gate round 1 adversarial W6a: the modal's Retry stays NON-primary,
  deliberately - Download is the form's one primary action; two primary
  buttons side by side in the error state would compete.)
- One-off MODAL (watch page): Retry stops being a floating small button
  above Download - the modal gets ONE action row; on error the row
  shows Retry (primary) beside Download-disabled-or-hidden per current
  lifecycle; visually one consistent block. Wiring (onRetry handler,
  buildOneShotRetryBody) unchanged.
- Inline style attributes on the touched buttons/status elements move
  into classes (no behavior change).

## Track C - unified busy/progress feedback (ask 3, design ours)

- ONE shared helper in common.js (`bindActionStatus(el)` returning
  {set(text, opts), clear()}) + `.action-status` CSS: secondary color,
  `--fs-xs`, reserved min-height (no layout jump - v1.26.2's lesson
  stays honored), optional leading inline spinner glyph while running,
  error tone class for failures. (restore-status stays field-error -
  see the survey correction above.)
- Busy buttons: `.btn-busy` - disabled + in-button spinner via CSS
  (::after), label preserved; applied by the same helper
  (`busy(btn)/idle(btn)`).
- Replaces: the three subscriptions header spans (kept as elements,
  restyled + text set through the helper), oneshot `<small>`, the four
  bold setup scan spans, logo-status, restore-status, modal status div.
  aria-live/role attributes preserved verbatim.
- The corner chip remains the canonical DETAILED view (Dean: chip
  approved, but not everything-in-the-corner) - page strips stay
  one-line summaries.

## Track D - collapsible sections (ask 4)

- Extend the existing `<details class="sub-collapsible">` pattern
  (already era-styled) to:
  - subscriptions: "Your subscriptions" list, failure log section
  - setup: every `.setup-box` (Branding, Video folders, Books, Music,
    Preferences, Automation/Scan+Cache, Account, Users, Backup)
  - stats: its long sections
- Collapse state persisted per-section in localStorage
  (`ft-collapse:<page>:<key>`) - same localStorage-only posture as
  bottom-bar prefs (tech-debt #42), disclosed the same way.
- Defaults preserve today's layout: everything currently visible starts
  OPEN; the two existing disclosures keep their closed defaults. The
  boxes `hidden` by capability (users-box, backup-box) keep their
  `hidden` attribute logic UNCHANGED - collapse is orthogonal to
  capability-gating (guard: a collapsed-open write must never unhide a
  capability-hidden box).
- SPA note (tech-debt #34 class): setup/subscriptions/stats are
  full-shell pages; `<details>`/summary needs no JS beyond persistence,
  so no view-root lifecycle risk. Persistence handler wired per page
  init with the view's abort signal where SPA-swapped.

## Known gaps / accepted residuals (living)

- Collapse prefs are localStorage-only (per-browser), same as #42.
- Era skins: action-bar uses existing tokens; device pass arbitrates
  the 2005/2009 bevel look (CSS-blind gate).
- (Gate round 1, adversarial S2) "Your subscriptions" now carries TWO
  collapse systems: the new details card and the v1.32 "Hide
  subscriptions (N)" toggle (ft_subs_collapsed) inside it. A user with
  the old toggle collapsed sees an open card with a hidden list -
  functional, but two affordances for one idea. Unify next wave.
- (Gate round 1, adversarial S3) The three 1s-polled scan status spans
  deliberately do NOT carry aria-live (per-second announcements for
  minutes = screen-reader chatter); the pre-existing
  automation-scan-status keeps its historical aria-live, and
  event-driven lines (logo, subscriptions header trio) announce
  normally. Announce-transitions-only is the better future shape.
