# v1.77.0 - Folder glyph pool (choose your folder's icon, in every set)

Status: ACTIVE
Branch: `release/v1.77.0`
Intake: Dean, 2026-08-04 (7 questions, all agreed - recorded verbatim below)

## The ask

Dean: "for the folders, we have glyphs available. The ones we have are great
but I'd love to be able to change them out of a pool. For example if I have a
Shows folder i'd like a TV glyph. Additionally each glyph we choose should be
out of a set of four for the different eras. The ones I want to add in addition
to the base are for the following things: School, Movies, Shows, Documents. Out
of all of the glyphs right now it looks like Liked is a full star and needs more
in its set." Then: "you pick a bunch of other things first", and "we have to add
a little drop down in the settings menu for the folders. and for books and
podcasts."

## Intake rulings (all AGREED)

1. **The axis is icon SETS, not eras.** There are 4 eras and 4 sets but they are
   not 1:1 - `AUTO_ERA_ICON_MAP` sends BOTH 2005 and 2009 to `emoji`, and
   `outlined` is never auto-selected by any era (explicit pick only). "A set of
   four" concretely means outlined SVG + rounded SVG + filled SVG + emoji
   codepoint.
2. **Period-correct substitutes where a set lacks a glyph**, disclosed in the
   README - never a silent fallback. (See "What measurement changed" below:
   zero substitutes turned out to be needed.)
3. **Liked gets its own class.** `.icon-liked` is minted with full four-set
   coverage; `.icon-star` is left to the Stats links.
4. **The pool is 20 glyphs** (Dean's 4 + 16 picked here), listed below.
5. **Every Library entry gets a picker**, not just Books and Podcasts - Music,
   Downloads and History too. Leaving 3 of 6 unconfigurable is the half-parity
   this repo has been bitten by.
6. **Out of scope:** retro-fitting the 10 existing base-asset-only glyphs
   (heart/share/flame/history/queue/podcast/downloads/books/grid/list) to full
   four-set coverage. Goes to the tech-debt tracker.
7. **Persistence:** folder glyphs are per-folder GLOBAL (in `folderSettings`,
   whitelist widened); library glyphs are per-user SERVER-persisted, riding the
   v1.67 card-corner lane.

## What measurement changed (two premises corrected before a line was written)

**a. `.icon-star` has nothing to do with ratings.** At intake I told Dean the
split was needed to protect the gold rating star. It is not: ratings render as
literal `★`/`☆` textContent in `.card-rating` (`main.js:1171`) and the watch
page's `#star-rating-control`. `.icon-star` is used by exactly 12 sites - the
Liked nav (10) and the Stats sidebar link (2). The comment at `style.css:4104`
("the gold ★ rating renders identically regardless of icon-set selection (AC8)")
describes a binding that does not exist. **It is a lying comment and this wave
fixes it.** The split still happens (Liked and Stats are different intents), the
stated reason was wrong.

**b. Zero substitutes are needed - but the README's provenance claim breaks.**
All 20 pool glyphs resolve HTTP 200 in all three upstream styles (measured
2026-08-04, 60/60). However `sports_esports`, `child_care`, `theater_comedy` and
`fitness_center` POSTDATE the June 2014 launch set. They are genuine Material
Icons *Filled* style (visually consistent with the bundled 14), but README.md's
claim that the `filled` set is "authentic to Material Design's original June 2014
release" would become false for them. The README is rewritten to describe the set
honestly as the Filled style, noting which members predate/postdate 2014, rather
than letting the set quietly outgrow its own description.

## Stops

### Stop A - the vocabulary
- `public/js/glyph-pool.js`: ONE source of truth, dual-mode (browser global +
  CommonJS export) so `server.js` and the client cannot drift. Server-side
  validation and client-side rendering read the SAME list.
- Fetch 57 assets from upstream (verified reachable). Symbols keep
  `viewBox="0 -960 960 960"`; Classic keeps `viewBox="0 0 24 24"` with the
  `fill="none"` bounding-rect idiom - both already match what is bundled.
- CSS: all 7 enumeration sites for all 20 classes.
- **Test that binds it:** iterate the registry and assert each member appears in
  all 7 CSS sites AND that its 3 SVGs exist and parse. A new pool member that
  misses one site fails CI. Extends the existing fill-parity test rather than
  duplicating it.

### Stop B - the `.icon-liked` split
- Mint `.icon-liked` (4 sets). Repoint all 10 Liked sites. Leave the 2 Stats
  sites on `.icon-star`.
- Fix the lying AC8 comment at `style.css:4104` to say what is actually true.
- **Test that binds it:** zero `icon-star` occurrences remain inside a
  `data-nav="liked"` block, across every static page - a count, not a spot check.

### Stop C - per-folder glyph
- Widen the `folderSettings` whitelist at `server.js:5903` (currently a hard
  3-key whitelist that would SILENTLY DROP a `glyph` field). Validate against the
  registry; unknown -> default `folder`.
- `resolveFolderGlyph(settings)` -> class name, garbage-defended, following
  `resolveCardCornerPrefs`'s posture.
- Apply at all **4** folder-row render sites.
- **Test that binds it:** the USE at each of the 4 sites, not the resolver's
  return value. This repo's most-repeated strike is "testing a DECISION is not
  testing its USE" (4+ recorded strikes). Each site gets a mutant check.

### Stop D - per-user library glyphs
- Add the 5 glyph keys to `MIRRORED_SETTING_KEYS` (`server.js:5390`); the
  existing `/^[A-Za-z0-9_-]{1,32}$/` value guard already fits registry ids.
- Resolver + application at `libraryEntriesHtml` and the static sidebar/bottom-nav
  markers.

### Stop E - Settings UI

### Stop F - docs, gate, release

## Named attack surfaces for the adversarial seat

1. **The 140 enumerations.** Delete one class from one of the 7 CSS lists and
   prove the suite catches it. The v1.47.6 failure mode (mask without fill =
   invisible box) must be unreproducible.
2. **The whitelist widening.** Can a crafted `POST /api/config` write a `glyph`
   the registry does not contain? Can it write a non-string? Can it survive the
   round-trip and reach `innerHTML` at any of the 4 render sites?
3. **XSS at the render sites.** The glyph value flows into a `class=` attribute
   in string-built `innerHTML` at 3 of the 4 sites. Break out of the attribute.
4. **Registry drift.** Mutate `glyph-pool.js`'s export and prove server-side
   validation and client-side rendering fail TOGETHER, not one silently.
5. **The Liked repoint.** Find a Liked surface that still renders `.icon-star` -
   including any injected at runtime rather than present in static markup.
6. **Stop C/D interaction.** A folder whose glyph is set, then removed from
   `db.folders`, then re-added: does a stale glyph resurrect?
