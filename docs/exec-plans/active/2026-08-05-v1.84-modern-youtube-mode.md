## 1. What Dean asked for (verbatim intent)

"Another loop on the YouTube feed" — make it feel more YouTube-ey, and add a
new opt-in **"Modern YouTube Mode"** checkbox distinct from today's feed. In it:
the three tile action icons restored on the tiles; a true modern grid (3-up
desktop / one big card on mobile); a mobile bar of **subscription avatars in
circles** for the channels that most recently uploaded, pinned at top; and a
single one-line **filter-chip row**: All · Videos · Audio · Podcasts · Continue
watching · Unwatched. "Really really match that view… super modern."

### Intake decisions (all Dean-confirmed)
1. **Three tile icons / "those buttons"** = the download/delete/like corner
   overlays. (They already exist + are always-visible on the CLASSIC grid card;
   they are ABSENT on today's default surface — see framing.)
2. **Layout, not a skin.** Modern mode is an ORTHOGONAL per-user toggle that
   composes with the era themes, not a new era.
3. **Chips are SERVER-driven** (whole-library scope — "Continue watching /
   Unwatched" can't be a client filter of the ~loaded page).
4. **Chips on desktop AND mobile; the channel-avatar bar is mobile-only** (matches
   real YouTube — desktop uses the sidebar for subs).
5. **All four card-polish touches:** channel avatar by title · "views · age"
   line · red watched-progress bar · rounded thumbnails.
6. **Desktop grid density: responsive 3→4** (3-up normal, 4 on very wide).
7. **Model (the hinge):** Modern mode = a **new flat big-tile grid** — one
   vertical feed of large tiles (3-up desktop / 1-up mobile) filtered by the
   chip row, with the mobile avatar bar on top. NO sideways shelves. The user
   picks between today's **Feed shelves** and the new **Modern grid**.

## 2. Framing: there are THREE home renderers (this is why "restore")

Confirmed by source scouts (client `public/js/main.js`, server `server.js`):

| Renderer | Trigger | Card chassis | Has the 3 icons / rich meta? |
| --- | --- | --- | --- |
| **Classic grid** | `homeFeed` off | `buildCardHtml` (`main.js:1217`), `#video-grid` | YES (overlays always-visible, views·age, byline, progress bar, stars) |
| **v1.79 Feed shelves** | `homeFeed` on — **the new-user DEFAULT** (`NEW_USER_DEFAULT_SETTINGS={homeFeed:'on'}` `server.js:5523`) | `buildFeedCardHtml` (`main.js:240`), horizontal `.books-home-row` scrollers | NO (stripped: id,kind,title,subtitle,thumb,href,progressPercent) |
| **Modern grid** (THIS wave) | `modernMode` on (NEW) | rich tile in a flat 3→4 / 1-up grid | YES + channel avatar + chips + mobile avatar bar |

Dean confirmed he sees the **shelves** today → that is exactly why the three
icons and rich meta feel "gone," and why he wants them "restored." Modern mode
is the clean third option, not a patch of either existing one.

**Toggle precedence** (two per-user booleans, documented): `modernMode` >
`homeFeed` > classic. If both are on, Modern wins. (A future refinement could
fold both into one 3-way "Home layout" radio; out of scope here — Dean asked
for "an additional checkbox.")

## 3. Architecture — the seams (machine-derived anchors; re-verify at each commit)

### 3a. Setting plumbing (mirror `homeFeed` / `starRatings` exactly)
- **Server:** add `'modernMode'` to `MIRRORED_SETTING_KEYS` (`server.js:5509-5515`).
  Value is the bounded STRING `'on'`/`'off'` — passes the existing
  `/^[A-Za-z0-9_-]{1,32}$/` validator (`server.js:5536-5538`), NO new validation.
  Do NOT add to `DEFAULT_SETTINGS` (instance-level; a `database.test.js`
  deep-equal guards it — `server.js:8427`). Read back off `GET /api/auth/me`
  → `settings.modernMode` (`server.js:5466-5483`). Absent ⇒ off.
  Leave `NEW_USER_DEFAULT_SETTINGS` as `{homeFeed:'on'}` (do NOT default modern on).
- **Client (`common.js`):** `applyModernModePref(value,opts)` +
  `bootModernModePref()` modeled on `applyStarRatingsPref`/`bootStarRatingsPref`
  (`common.js:262-285`) and `bootHomeFeedPref` (`common.js:316-325`). Sets
  `document.documentElement.setAttribute('data-modern', on?'on':'off')` (or a
  root class), writes localStorage, reflects `#modern-mode-check`, mirrors
  `{modernMode:v}` via `mirrorUserSetting` (`common.js:116-124`) only when
  `opts.mirror`. Seed on first cross-device load from `fetchCurrentUser()` (its
  own boot fn, registered near `common.js:10902`, NOT folded into the
  early-returning `pullMirroredDisplayPrefs`).
- **UI:** `#modern-mode-check` checkbox in `setup.html` Appearance `<details>`
  (near `setup.html:158`); `wireModernModeControl(signal)` in `setup.js` cloned
  from `wireHideStarsControl` (`setup.js:558-567`).

### 3b. Flat modern-grid data (extend `GET /api/home`)
The chips need a FLAT, mixed-kind, chip-filtered item list — the row-grouped
`/api/home` and the videos-only `/api/videos` neither fit alone. Extend
`/api/home` (`server.js:9289-9412`) with a grid view:

- New params: `?view=grid&filter=<all|videos|audio|podcasts|continue|unwatched>`.
  When `view=grid`, return `{ items:[...] }` FLAT (bypass `assembleHomeRows`).
- Reuse the existing per-user reads unchanged: `watchedSet`, `progressMap`
  (+pending overlay), `likedSet`, hidden-folder filter (`server.js:9304-9306`),
  `subNames` (`9312`). This preserves RBAC visibility + read-your-writes.
- **Carry `item.type`** (`'video'`/`'audio'`, `server.js:4201`) onto the media
  candidate record (add at `server.js:9344-9355`) — REQUIRED to split
  Videos/Audio (today `kind:'media'` mixes both).
- Filter map: `videos`→media & type==='video'; `audio`→media & type==='audio';
  `podcasts`→kind==='podcast'; `continue`→`inProgress` (`9336`);
  `unwatched`→`!watched` (`9331`); `all`→no filter.
- **Enrich the emitted item** beyond `resolveHomeItem`'s current fields
  (`server.js:9269-9287` emits only thumbnailUrl): add `channelName`,
  `channelAvatarUrl` (via `ytdlp.resolveItemChannelAvatarUrl` `store.js:877`),
  `sourceViewCount`, `addedAt`, `type`, `duration`, `liked`. Drop dead links
  (`9405-9406`) as today.
- Order: recency (`addedAt` DESC) for a YouTube-home feel; cap generously
  (e.g. 60) — a `log()`-style disclosed cap, not silent.

### 3c. Modern grid renderer (`main.js`)
- Home render gate (`main.js:711` area): compute `modernMode`; precedence
  `modern > feed > classic`. When modern: add root class `modern-home-mode` +
  `data-modern`, mount `#modern-home-host`, call `renderModernHome`.
- `renderModernHome(host, signal, filter='all')`: fetch
  `/api/home?view=grid&filter=<filter>`; render (mobile) the avatar bar, then
  the chip row, then a flat grid of `buildCardHtml` tiles (rich card reused).
  Active-chip is client state; changing chip re-fetches (abort the prior via
  signal). Reuse the existing delegated `#video-grid` click handlers by giving
  the modern grid the same hooks, or a parallel delegated listener.
- Pure helper `resolveModernChip(raw)` (allowlist → 'all') unit-tested; the
  render is thin over it.

### 3d. Mobile channel-avatar bar (reuse `GET /api/channels`)
`/api/channels` (`server.js:9427-9459`) already returns
`{folder,name,avatarUrl,count,latestAddedAt}` per channel. Pure helper
`selectRecentUploaderChannels(channels, subNames, cap)`: keep subscribed, sort
`latestAddedAt` DESC, cap N. Render circles (avatar `<img>` or monogram via
`resolveAvatarSource`), each linking to `/?folder=<key>`. Mobile-only via CSS.

### 3e. Card polish (additive to `buildCardHtml`, mostly already present)
- **Channel avatar by title:** call `resolveAvatarSource(channelName,
  item.channelAvatarUrl)` (`common.js:401`) in `buildCardHtml` (`main.js:1237`
  area), emit a span beside `.video-uploader`. Monogram fallback when the URL is
  absent (it usually is), so this works with zero server backfill.
- **Views·age line:** ALREADY on the classic card (`.video-meta`, `main.js:1276`)
  — verify it renders in modern; no rebuild.
- **Red progress bar:** `.progress-bar-fill` ALREADY on the card; verify the fill
  is `--yt-red` and shows in modern. Style-only if not.
- **Rounded thumbnails:** CSS under `[data-modern]`.

### 3f. Modern CSS (`public/css/style.css`)
`[data-modern="on"]`-scoped block (view styles belong in style.css — the SPA
swaps only `#view-root`): grid `repeat(3,1fr)`→`repeat(4,1fr)` responsive,
1-up under the phone breakpoint (the real `repeat(2,1fr)` today lives in the
480px block `style.css:6765`); rounded thumbs; the chip row (one line,
horizontally scrollable, active-chip pill); the mobile avatar bar; tile-icon
prominence. **Design tokens ONLY — `npm run lint:css` must stay TOTAL 0.**
Remember `:root` custom props kill `var()` fallbacks; every era must still look
right (modern is orthogonal to era, so test against ≥2 eras).

## 5. Gate brief (FULL — QA + adversarial)

**Named attack surfaces for the adversarial seat:**
1. **Metadata-leak (v1.80 class):** does `/api/home?view=grid` leak TITLES/avatars
   of hidden or RBAC-invisible folders/channels? Enumerate the new read surface;
   diff against the hidden-folder + visibility filters the row path uses.
2. **Write-gate (v1.81 class):** the delete/download icons on modern tiles — does
   the delete affordance honor `canModifyLibrary` (hidden for capability-less
   members, `buildCardCornerButtonsHtml` caps)? Mutation-test the cap.
3. **Cross-user isolation:** watch-state/progress/continue/unwatched must use the
   acting user's data only — every test uses ≥2 distinct users (the actor-vacuity
   scar), NOT user 1 alone.
4. **Chip filter correctness:** video/audio/podcast/continue/unwatched each return
   exactly their set; `type` actually carried (a divergent-fixture test).
5. **Toggle precedence + persistence:** modern>feed>classic; mirror round-trips;
   absent⇒off; no `DEFAULT_SETTINGS`/`database.test.js` deep-equal breakage.
6. **Census + era orthogonality:** `lint:css` TOTAL 0; modern renders correctly
   over ≥2 eras (no `var()`-fallback death).
