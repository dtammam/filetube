# v1.94.0 - Animated hover preview clips (the YouTube hover feel)

Status: ACTIVE (building). Owner: main session. Gate: FULL (new media generation
+ a new servable sidecar + client rework).

## Why (Dean's realization, on-device)
The storyboard *card* hover (a slideshow of sampled stills) never feels like
YouTube because it isn't video. YouTube's hover preview is a short **muted video
clip** that plays. The storyboard *scrub* preview (seek bar) is a SEPARATE
YouTube feature (sampled stills for random-access scrubbing) and is loved -
KEEP IT. This wave replaces only the CARD hover with a real preview clip.

Dean's decisions (intake): **muted MP4 clip** (not GIF/WebP) + a **montage
across the video** (not first-N-seconds).

## What ships
A per-video **preview clip**: a ~6s muted MP4 montage of ~4 short (~1.5s)
snippets sampled across the interior of the video (skip intro/outro), scaled to
320px, H.264 + yuv420p + `+faststart`, no audio track. Plays/loops on card
hover (desktop) / in-view (mobile), replacing the storyboard card slideshow.

- **Keyed disk-side** (the v1.93.2 lesson): the clip is a sidecar keyed by file
  EXISTENCE, eligibility DERIVED from duration - NO persisted DB flag. New route
  `GET /preview/:id` (RBAC-gated like /thumbnail, /storyboard). Scan heal keys on
  the on-disk clip -> converges with no dependence on a completed pass.
- **Memory-bounded generation** (the v1.93.1 lesson): one ffmpeg pass with N
  fast input-seeks -> trim -> scale -> concat -> encode. N=4 short decoders +
  one x264 encoder, NO temp files. Bounded and cheap vs a full transcode.
- **Client load-guard** (the v1.93.2 lesson): the `<video>` reveals only on
  `canplay`; a 404 (clip not generated yet) leaves the poster - never a black
  box. Keeps the ~1.5s start delay + the mobile 2-at-a-time cap (v1.93.3).
- **Two assets per video now**: storyboard sprite (scrub) + preview clip (hover),
  doing two different jobs (random-access stills vs linear motion). Both join
  ALL sidecar lifecycle sites (trash/restore/move/prune/purge) + a binding test.

## Tasks (each green before the next)
- T1 (lib/previewClip.js, PURE, unit-tested): `planPreviewClip(duration)` ->
  `{v, snippets:[t...], dur, count, width, fps}` or null (ineligible/short);
  `buildPreviewClipArgs(src, out, plan)` -> the exact ffmpeg arg array;
  `previewClipEligible(item)`.
- T2 (server): `previewClipPath(id)`, `extractPreviewClip`, disk-keyed
  `restoreMissingPreviewClip`; wire into the scan (new-item + reuse + legacy),
  same pattern as the storyboard heal (writes NOTHING to db). Join the 6
  lifecycle sites for the new `<id>.pv.mp4` sidecar.
- T3 (server): `GET /preview/:id` (RBAC `mediaVisibleTo` + eligibility + on-disk
  file, video/mp4). Send `hasPreview: true` (derived `previewClipEligible`) in
  the 4 card/watch payloads so the client only wires eligible video cards.
- T4 (client): a preview-clip hover controller (repurpose StoryboardCards' delay
  + in-view + cap machinery) that creates a `<video muted loop playsinline
  preload=metadata>` over the poster, reveals on `canplay`, poster on error;
  RETIRE the storyboard card slideshow (`.card-preview` frame-cycling). The
  storyboard SPRITE + the player.js scrub preview are UNTOUCHED.
- T5 (tests): unit (planner exact snippet points at boundaries; arg array;
  eligibility divergent fixtures); integration (serve + RBAC 404; lifecycle
  trash->restore->purge of the .pv.mp4; scan backfill + 2nd-scan converge).
- T6: full gate -> dual-Node -> release v1.94.0. Backfill: another full pass
  (video encode); disclose the cost + the on-device RSS probe on the big tail.

## Predictions (machine-derived at each commit, not hand-enumerated)
- Sidecar lifecycle sites for `.pv.mp4` == the count for `.sb.jpg` (grep the
  storyboardPath lifecycle sites; the new sidecar joins the SAME set).
- Card/watch payloads sending `hasPreview` == the set sending `storyboard`
  (videos/:id, videos list, resolveModernGridItem, /api/liked).
- rbac-census route count +1 (the new `/preview/:id`).

## Known risks (disclose)
- No ffmpeg on the dev box: the encode command is verified by unit args + the
  gate + Dean's device (peak RSS on the 3-6.5 GB tail; N=4 decoders ~ bounded).
- Mobile plays real video on scroll (heavier than stills) -> the 2-cap + muted
  inline + preload=metadata; Dean's device judges battery/feel.
- iOS muted-inline autoplay needs `muted` + `playsinline` (+ a user-gesture-free
  play() which iOS allows for muted inline) - device-verified.
- Another full backfill (video encode, heavier than sprites).
