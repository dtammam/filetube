## 1. Outcome (Dean's words, 2026-10-06)

The complaint is the OPPOSITE of the ROADMAP title: "The random genre change is rough. Less repetitive more too random. I like
the idea of it being the same artist/genre. It gets real random after a point." Plus "Bland / no direction". So:

1. Autoplay plays like a station: it stays near where it started (same artist, same genre, nearby years) and drifts slowly, never
   jumping to an unrelated genre, and never one artist four times in a row.
2. Dean can start that station from a song, an artist, an album or a genre.
3. A Shuffle mode toggle exists for when he wants random on purpose.

Tuning from T0 (builder, stated per the R7-R12 latitude; Dean's device pass is the arbiter):
- **YouTube categories are not genres.** On yt-dlp audio (`source` library / library-chapter) a primary genre that is a YouTube
  category name (Music, Gaming, People & Blogs, Entertainment, Comedy, ...) counts as untagged, so those tracks fall to T5 (same
  folder / channel) instead of a "genre" tier that would span every music upload (today's randomness by another name); a new T6
  (same YouTube category) sits after the folder tier for such a station, and the old T6 (the rest) becomes T7. A station seeded
  FROM a category genre row plays its members. Genre keys also fold `-` / `_` / spaces (`hip-hop` = `hip hop`).
- **Untagged seeds borrow a genre:** the seed artist's most common genre, else its folder's; a station with neither a genre nor a
  category anchors on the most common genre of its last 20 plays (so it keeps a direction instead of jumping per pick).
- **Artist cap per hour.** The "at most 3 per hour" target conflicts with 2 seed-artist slots in every batch of 5 at ~19 tracks an
  hour. Added: an artist with 3 plays in the last 20 (an hour at T0's span mode: 19 median, 21 p90) is skipped like a spacing
  breach (widening to a farther CLOSE tier; relaxed, window first and the 2-in-a-row rule last, before an unrelated genre). The 2
  seed-artist slots per batch stay; the cap is what spreads them.

## 4. Rulings

R1-R6, R13 and R14 are Dean's answers (2026-10-06). R7-R12 are the kickoff's design defaults inside his "close, with slow drift"
ruling, not his words: the builder may tune their constants from T0 and states each change; Dean's device pass is the arbiter.

| # | Question | Ruling |
|---|----------|---------|
| R1 | What is wrong | Too random, not too repetitive: genre jumps, "gets real random after a point", bland / no direction. Same artist and genre is GOOD. |
| R2 | Ambition | Smarter picker + "Start radio" from a menu. No named stations, no pocket radio row (ROADMAP Planned). |
| R3 | Start radio from | A song, an artist, an album, a genre. |
| R4 | How tight | Close, with slow drift: mostly same artist + same genre + neighbouring years, widening only when the close pool runs low; never a jump to an unrelated genre; artist spacing so one artist never plays 4 in a row (R12: at most 2 in a row). |
| R5 | Shuffle | A Shuffle mode TOGGLE in this release, beside Loop and Autoplay: ON reshuffles the songs after the current one; OFF restores the original order of the songs not yet played. Radio picks appended while Shuffle is on stay coherent (Shuffle reorders, it never widens the pool). |
| R6 | Release shape | Radio = v1.368.0 (this branch). Playlist picker = v1.369.0. Cleanup + subtitles + 360 = v1.370.0. |
| R7 | Where the picker runs | SERVER-side, one pure function over the viewer's visible library (the same RBAC + projection `GET /api/music` uses), so it is unit-testable, the simulator can import its logic, and the client keeps only trigger + append. |
| R8 | Station anchor | A station has a SEED (track, artist, album or genre) that every batch is drawn against, not "the last track" (today's anchor walks away one batch at a time, which is part of the drift). Plain Autoplay seeds from the track that was playing when the queue ran out. |
| R9 | Similarity tiers (draw order, widening only when a tier is exhausted for this session) | T1 seed artist (artist OR albumArtist); T2 same primary genre and year within 5; T3 same primary genre; T4 a neighbouring genre (two genres are neighbours when the library has an artist with tracks in both; strength = number of shared artists); T5 same folder / channel (the fallback for untagged tracks); T6 the rest of the library only to avoid silence. A batch mixes tiers rather than draining T1 first (e.g. 2 from T1, 3 from T2-T3) so the seed artist recurs but does not dominate; exact mix set from T0. |
| R10 | Likes and recency | A liked track weighs about 2x within its tier; a track whose stored progress `updatedAt` is within the last 24 h weighs less (soft cool-down across reloads with no new storage). No new tables. |
| R11 | Session memory | Keep the client's played list (sent as the exclude list, capped at the last 200 ids); never repeat a track in a session until its tier is exhausted, then the least recently played first (no silence). |
| R12 | Artist spacing | Never 3 in a row from one artist; at most 2 per batch of 5 from the seed artist after the first batch. |
| R13 | Chapter picks (Dean) | A radio pick that is a chapter of a DJ-set file plays THAT chapter and stops at its end (the v1.311 solo-exit rule), never rolling through the rest of the set. |
| R14 | Start radio behaviour (Dean: replace the queue) | Replaces the queue: the seed (the song; the artist's or album's or genre's first coherent pick) plays now, then the station extends as Autoplay does. It turns Autoplay on if it was off (with a toast saying so) so the station can continue. The queue context records the seed so a resume keeps the station. |

### W3. Shuffle mode toggle (R5)
- A Shuffle toggle beside Loop and Autoplay on every surface that has them: desktop `#music-*-btn` row (`reflectPlaybackModes`),
  the mobile skin sticker menu, the pop-out. State key `ft-music-shuffle`, synced like `ft-music-autoplay` (add to
  prefs-sync.js AND lib/prefs-allowlist.js: LESSONS 12 sibling list; bind both).
- ON: the songs after the current one are shuffled (Fisher-Yates, the current track stays put, already-played stay behind); the
  original order of the not-yet-played tail is kept so OFF restores it (a song added while ON is placed at the end of the
  restored order). Radio picks appended while ON are inserted at random positions among the not-yet-played songs, never ahead of
  the next track the user can see as "Up next" if that would hide a user-queued song (builder states the rule and tests it).
- The existing one-shot Shuffle buttons (Music page, album/artist Shuffle, iPod Shuffle Songs, `?mode=shuffle`) keep working
  and do not flip the toggle.
- **Falsifier:** tests: ON keeps the current track and the played prefix byte-identical and permutes the tail; OFF restores the
  exact original tail order; toggle on another device (storage event / prefs sync) reflects on this one; mutants: shuffle the
  played prefix (red), lose the original order (OFF test red), drop the allowlist entry (sync test red).
