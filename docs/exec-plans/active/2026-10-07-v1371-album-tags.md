## 1. Outcomes

1. In the playlist picker, with Format = Audio, a "Save as an album" switch reveals Album (defaults to the playlist title),
   Album artist (defaults to the most common first-credited artist) and a "Clean up titles" switch (off by default).
2. Downloaded with it on, every chosen track lands in Music as ONE album under the album artist, numbered in playlist order.
   A track with no credited artist (an official-channel upload) shows the album artist, not the channel handle; a track
   that credits artists keeps them ("Kyle Gordon, Daniel Radcliffe").
3. With "Clean up titles" on, "Kyle Gordon - Planet of the Bass (feat. X) [Official Audio]" reads "Planet of the Bass
   (feat. X)". A feat. credit and a meaningful tag like "[Instrumental Version]" stay.
4. Nothing changes for video, for a single one-off, or for a subscription (their argv is byte-identical).

## 2. What exists (recon 2026-10-07)

- **Why "Unknown Album":** a downloaded audio file is a MEDIA item projected into Music by `lib/music/libraryAudio.js`
  `projectAudioItem`: album = the embedded `album` tag ONLY ("never the path slug", line 133), artist = the `artist` tag else
  the channel name, album artist = the `albumartist` tag else the artist. The client paints '' as "Unknown Album"
  (`public/js/music-skins.js:925`). The previous builder's folder-fallback prediction was about `lib/music/tags.js
  parsePathConvention`, which only the native music scan uses. So the fix is real tags in the file.
- **Tags reach Music:** server.js `parseFfprobeTags` keeps album, artist, title, track, and maps `album_artist` to
  `albumartist` (server.js:2178-2181). The album key is `albumArtist||artist` + album (`lib/music/store.js albumKeyFor`).
- **yt-dlp writes tags today:** every download carries `--embed-metadata` (lib/ytdlp/args.js:1311). yt-dlp's FFmpegMetadataPP
  (`postprocessor/ffmpeg.py _get_metadata_opts`) writes any info field `meta_<key>` as the file tag `<key>`, after its own
  mapping, so `meta_album`, `meta_album_artist`, `meta_track`, `meta_title`, `meta_artist` set the tags without touching
  `title` (the file name, `-o %(title)s`, stays as today).
- **The picker:** `openPlaylistPicker` (public/js/common.js) posts `{listId, title, ids, format, quality, filetype}` to
  `POST /api/ytdlp/download-playlist`; `playlistJobFrom` validates it (and a pending entry after a restart);
  `runPlaylistJob` runs each id through `launchOneShotJob` -> `runOneShot` -> `run.runDownload` -> `buildYtdlpDownloadArgs`.
  Flat playlist rows (`run.playlistEntryFrom`) carry id, title, duration, thumb, unavailable; the raw yt-dlp row also has
  `channel` (test/fixtures/ytdlp-playlist/example-list-PLUtyNbQXMTLg.json is Dean's own Kyle Gordon list).

## 3. Measurements (yt-dlp 2026.08.19 from the dev box, 2026-10-07)

- **Literal values through `--parse-metadata` + `--replace-in-metadata` (real download of QFIFEobmIIQ, ffprobe read-back):**
  `--parse-metadata 'pre_process:%(id)s:(?P<meta_album>.+)'` seeds the field, then
  `--replace-in-metadata 'pre_process:meta_album' '(?s).+' '<value>'` sets it. ffprobe read back album, album_artist "Brat"
  (a single word: a bare literal as FROM would have been read as a FIELD name, `field_to_template`), track 7, the title.
  The value is a Python `re` REPLACEMENT: `\g<0>` in it was substituted with the video id, so `\` must be doubled; `%`, `"`,
  `:`, `[`, `$1` passed through literally. The explicit `pre_process:` WHEN prefix is required, or a value starting with a
  WHEN name (`video:`) would be eaten (`options.py _dict_from_options_callback`).
- **Artist only when none is credited:** `--parse-metadata 'pre_process:%(artist,creator|)s:(?P<meta_artist>.*)'` then
  `--replace-in-metadata 'pre_process:meta_artist' '^$' '<album artist>'`. Official upload QFIFEobmIIQ / 4uDlOoSMH88: artist
  NA, meta_artist = "Kyle Gordon" (ffprobe: artist "Kyle Gordon"). Art track c1Paj8je5sM: artist "Kyle Gordon, Daniel
  Radcliffe" kept; its own album was "Mr. Jambo (feat. Barry Bergen)" (the single), which is why the album must be overridden.
- **Title cleanup on real titles:** seed `meta_title` from `title`, strip `(?i)^<artist, regex-escaped>\s*[-–—]\s*`, strip
  bracket groups naming official/audio/video/lyrics/visualizer/HD/4K/HQ/MV that do not start with feat/ft/with, collapse
  spaces. "Kyle Gordon – My Life (Is the Worst Life Ever) [feat. Our Wounded Courtship] [Official Music Video]" ->
  "My Life (Is the Worst Life Ever) [feat. Our Wounded Courtship]" (note the EN DASH separator).

  downloaded playlist misses those tracks: disclosed in the release note.

  single-flight).
- A video ANY user already has (its YouTube id in the library) downloads with no album tags (gate r1 W1). A file on disk
  that the scan has not indexed yet is not known and would be re-tagged by yt-dlp's embed pass.

  playlist's album (gate r1 W3).
- Opus is not offered (its tags are per stream). A title made only of noise ("[Official Video]") cleans to an empty
  title tag, and Music falls back to the file name.
