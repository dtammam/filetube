# v1.95.0 - Mobile touch targets (bigger hit areas, same look)

Status: ACTIVE (building). Owner: main session. Gate: FULL (broad client CSS +
the battle-won seek-drag path).

## Why (Dean, on-device)
The mobile controls are too small / need super-precise touch - day-to-day
friction. He likes the current look, so: **bigger HIT AREAS, same visual**, done
as ONE systematic mobile pass (not per-control one-offs) so future controls
inherit it. Named pain points: the resume/start-over buttons, the queue x + up/
down arrows, the notification x, and - the one he stressed most - the PLAYER
SEEK HANDLE he keeps missing.

## Machine-derived facts (from the scout - do NOT hand-guess)
- Mobile CSS convention = `@media (max-width: 768px)` (NO `pointer:coarse`/
  `hover:none` queries, NO body mobile class - the codebase has neither). Match it.
- Token `--size-touch: 44px` already exists (style.css:148). The EXEMPLAR is
  `.pc-btn` (32px desktop -> 44px mobile, style.css:5933) - replicate that shape.
- Census-governed props: color/font-*/line-height/letter-spacing/z-index/shadow/
  motion/border-radius/**spacing (margin/padding/gap/inset/top/right/bottom/left)**.
  **width/height/min-*/max-* are NOT governed** - so `min-height/min-width:
  var(--size-touch)` is free; any padding/gap/font/color I touch must be a token.
- Controls with NO >=44px mobile floor (the surface): `.queue-row-move`
  (style.css:10005), `.queue-row-remove` (10060), `.notif-row-dismiss` (36px,
  9497), the resume `.btn`s (.resume-actions 2172 / .btn 895), the 6 card-corner
  btn classes (1418+), and `.pc-range` seek band (16px, 5592; row grows to
  --size-touch but the INPUT stays 16px).
- Seek drag is `pointerdown`+setPointerCapture+doc-level `pointerup/cancel` on
  `#seek-bar` (`.pc-range`), `touch-action:none` (player.js:4759-4784). The
  storyboard-scrub `pointermove/down` pair (4689) rides the same element. REUSE
  these - do not rebuild (the battle-won lesson).

## Approach
1. **Isolated controls** (grow the box is fine): `min-height/min-width:
   var(--size-touch)` + flex-center the glyph, inside `@media (max-width:768px)` -
   the `.pc-btn` pattern. Same visual glyph, 44px tap box.
2. **Tightly-packed controls** where growing the box breaks layout (stacked queue
   up/down arrows; adjacent card corners): extend the HIT AREA outward WITHOUT
   layout change via a `::before { position:absolute; inset:-Npx }` (a pseudo-
   element is not a separate event target - a hit in its box targets the host),
   with DIRECTIONAL insets for stacked pairs (up-arrow claims up+sides, down-arrow
   down+sides) so their zones don't overlap ambiguously. Host needs
   `position:relative`.
3. **Seek band** (the priority): on mobile, make `.pc-range` a tall TOUCH BAND
   (min-height ~44px) so a tap anywhere near the line grabs the scrubber, while
   the VISUAL track stays thin (track/thumb styled separately) - and a bigger
   thumb on mobile. Keep `touch-action:none` + the pointer-capture handlers +
   scrubRatioFromPointer (rect-based, unaffected by height). Firefox `::-moz-*`
   mirrors the `::-webkit-*` rules.
