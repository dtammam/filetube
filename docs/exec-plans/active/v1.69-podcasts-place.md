# Podcasts place + RSS subscription engine (v1.69.0) - exec plan

STATUS: DESIGNED 2026-08-02, Dean's intake rulings given same day (do NOT
re-intake):

1. **What counts as a podcast: the subscription decides** - an RSS
   subscription is always a podcast; an existing yt-dlp audio subscription
   gets a per-subscription "file under Podcasts" toggle. No file-shape
   heuristics, ever. (agreed)
2. **Episode experience** - show page per subscription, episodes
   newest-first, per-user played/resume state. Position-sync-mid-episode
   across devices and auto-delete-after-played are OUT of scope. (agreed)
3. **One wave** - Dean explicitly overrode the recommended two-wave split:
   engine + place ship together as one massive wave. (his ruling)
4. **No cookie-based scraping** - paid Patreon is served by the RSS lane
   (Patreon's own podcast-app export mechanism); yt-dlp keeps covering the
   YouTube-shaped sources it already handles. A paid source with no RSS
   export is a future intake, not this wave. (agreed)

Earlier rulings from the same intake (first round, accepted by "you're
kind of already hitting it" + go): standing subscriptions (not one-shots)
with back-catalog backfill; enclosures downloaded byte-true when already
mp3 (ffmpeg-convert only for non-mp3 enclosures - deferred, see D14);
one folder per show under a podcasts root.

FULL two-reviewer gate, never slim: this wave stores a live credential
(Patreon feed auth tokens), fetches user-supplied URLs server-side, and
writes/deletes files. Adversarial seat briefed to: leak the token (logs,
API responses, status strings, backup bundles, error paths), reach
internal hosts via feed URL / enclosure redirects, abuse the parser
(malformed XML, entity bombs, giant feeds, hostile titles/guids), escape
the show directory via feed-controlled strings, and destroy data via
backfill interruption / reconcile prune / mount loss.

## Live-feed facts (measured 2026-08-02 against Dean's real Patreon feed)

- Feed: HTTP 200, `application/rss+xml`, **490,401 bytes on ONE line** (the
  parser cannot be line-based). RSS 2.0 + itunes namespace.
- **484 items; every one has `<enclosure url=... type="audio/mpeg">`, all
  .mp3, all enclosure hosts `www.patreon.com`**; per-item `<guid
  isPermaLink="false">` is the numeric post id; `<pubDate>` RFC-1123;
  `<itunes:duration>` in seconds; `<itunes:image>` at channel AND item level.
- Enclosure GET: **302 -> `c10.patreonusercontent.com`** (CDN), then 200
  `audio/mpeg`, `accept-ranges: bytes`. Redirect following is REQUIRED and
  every hop must be re-guarded.
- **Back catalog = 42.3 GB total, 87 MB avg** (sum of `length` attrs).
  Backfill must be paced (serialized, one enclosure at a time), durable
  per-episode (an interruption loses at most one partial file), and must
  not block other server work.
- **Secrets live in TWO places**: the feed URL query (`?auth=<token>`) AND
  every enclosure URL path (`/api/rss/u/<token>/e/<id>.mp3`). Both are
  Dean's Patreon identity for that feed. Redaction must cover both shapes.
- Token-redacted 5-item fixture built from the real feed (verified
  token-free by string search) -> becomes `test/fixtures` input for the
  parser suite.

## Design decisions

- **D1 - module layout.** New `lib/podcasts/`:
  - `store.js` - namespace owner. `db.podcasts = { subscriptions: [],
    episodes: {}, settings: {} }`. `ensurePodcasts` / `readPodcasts`
    split (P3). Subscriptions are an ORDERED ARRAY (music-folders style);
    episodes a guid-keyed map (null-prototype accumulators, hasOwnProperty
    discipline - the __proto__ hazard is a known repo bug class).
  - `feed.js` - PURE hand-rolled RSS extractor (D5). No I/O, no deps.
  - `fetchGuard.js` - feed fetch + enclosure streaming download built on
    the shortlink envelope (D6/D7). Injectable http/https/lookup/now.
  - `secrets.js` - the feed-URL secret store + redaction helpers (D3).
  - `index.js` - registerRoutes, poll timer, download orchestration,
    reconcile. Thin; every decision helper pure and unit-tested.
  - `views/` - none: the place is a first-class public page (D9), unlike
    the ytdlp module there is no secret in the client assets.
- **D2 - namespace + persistence (P1).** sqlite.js: `'podcasts'` joins
  `CONTAINER_KEYS`; `'podcasts.subscriptions'`, `'podcasts.settings'`
  join `SINGLETON_NAMES`; `'podcasts.episodes'` joins `DOC_KV_NAMESPACES`
  (per-episode row writes, the metadata pattern - a 484-episode backfill
  must not rewrite one giant blob 484 times). `'podcasts'` joins
  `BACKUP_NAMESPACE_KEYS` + known-keys + restore walk IN THE SAME COMMIT
  (v1.42 carrier law).
- **D3 - secrets.** Feed URLs are stored OUTSIDE the db, in
  `<DATA_DIR>/podcast-feeds.json`, 0600, `{ [subId]: feedUrl }`, written
  atomically (temp+fsync+rename), structurally excluded from backups
  (backups bundle db namespaces; this is not one - P7 posture). The db
  subscription record stores only `feedUrlDisplay` = origin + pathname
  (query ALWAYS stripped - a query string is treated as secret-bearing
  unconditionally, no classification heuristics) + `feedHost`. Every
  error/status string passes `redactSecrets(str)` which scrubs (a) every
  stored feed URL's query values and (b) the `/u/<token>/` enclosure path
  segment, before persistence or response. Restore-onto-fresh-box
  consequence DISCLOSED in ROADMAP: subscriptions restore from backup but
  tokened feeds need their URLs re-entered (a one-line "Feed URL needs
  re-entry" state per sub; poller skips those subs with an honest
  lastStatus).
- **D4 - subscription record.**
  `{ id, name, feedUrlDisplay, feedHost, addedAt, order, paused,
  backfill: 'all'|'new'|N, lastCheckedAt, lastStatus, checkFailures,
  backoffUntil, description, author, showDirName, secretMissing }`.
  (Amended at T3: NO remote imageUrl is persisted - Patreon image URLs
  carry token-hash query params, so the poller downloads the show cover
  to `<showDir>/cover.jpg` and the record stays URL-free; one less leak
  surface. `secretMissing` marks a restored sub whose token needs
  re-entry, D3.)
  `id = md5('podcast\n' + normalized feed URL)` via the injected
  `getMediaId`-style hasher - re-adding the same feed is idempotent.
  Default `backfill: 'all'` (Dean's stated goal is a true offline cache;
  yt-dlp's newest-only default deliberately NOT inherited). Backfill is
  a per-add choice in the UI: all / latest N / new-only.
- **D5 - the parser (feed.js).** A bounded scanner, not an XML DOM:
  extract `<channel>` header fields + every `<item>...</item>` span
  (works on one-line documents), then per-item regex field pulls for
  `title`, `guid`, `pubDate`, `enclosure url|length|type`,
  `itunes:duration`, `itunes:image href`, `description`, `link`. CDATA
  unwrapped; the five named XML entities + numeric character references
  decoded; DTD/external entities NEVER processed (the scanner simply has
  no entity-expansion machinery - XXE/billion-laughs are structurally
  inert; a `<!DOCTYPE` prelude is skipped, its internal subset ignored).
  Caps: input <= 25 MB (Dean's 484-item feed is 0.49 MB), <= 2,000 items,
  per-field length caps (title/guid 2 KB, description 64 KB) - all
  enforced with explicit truncation, never crash. Items lacking an
  audio enclosure are SKIPPED (kept count reported in lastStatus - a
  video-enclosure feed yields an honest "0 audio episodes", not a lie).
  Malformed input -> `{ ok:false, error }`, never throw.
- **D6 - feed fetch.** Manual-redirect GET, `guardHop` on the START URL
  and EVERY hop (private/loopback literal + DNS resolve-then-check,
  fail-closed), max 5 hops, per-hop 10 s / total 30 s, body cap 25 MB
  with mid-stream abort. https + http accepted (some free feeds are
  still http; the guard chain is identical). The TOCTOU rebinding
  residual is inherited from shortlink.js and disclosed (P5).
- **D7 - enclosure download.** Same envelope as D6 plus: streams to
  `<showDir>/.<final-name>.ptpart` and atomically renames on byte-count
  success; hard size cap 2 GB/episode (mid-stream abort over cap);
  wall-clock ceiling 60 min/episode; ONE download at a time through the
  heavy-job gate (D12); on any failure the .ptpart is unlinked and the
  episode record stays `pending` for the next poll (at-most-one-partial
  invariant; the feed's `length` attr is advisory only, never trusted as
  a completion check - the transfer's own end + >0 bytes + a 2xx is).
  `.ptpart` files are invisible to the place (episode records flip to
  `downloaded` only after rename) and swept on module start.
- **D8 - files + folders.** Root: `db.podcasts.settings.downloadDir`,
  default `<DATA_DIR>/podcasts`, env override `FILETUBE_PODCASTS_DIR`,
  operator-visible in the podcasts page settings sheet. Show dir =
  `sanitizeChannelName(feed title)` (the ytdlp sanitizer + confinement
  assert pattern, resolveChannelDir precedent). Episode filename:
  `<sanitized title, <=100 chars> [rss=<guidKey>].mp3` where `guidKey` =
  the guid itself when it matches `[A-Za-z0-9_-]{1,64}` (Patreon's numeric
  guids pass), else `md5(guid)` - the universal bracket contract
  (lib/ytdlp/url.js UNIVERSAL_BRACKET) holds, so `extractMediaRef`
  parses these files with zero changes. Episode id =
  `md5('podcast-ep\n' + subId + '\n' + guid)` - stable across file moves.
  The podcasts root joins the FOUR-way root-overlap rejection (P3) in
  the same commit that creates it.
- **D9 - the place.** `public/podcasts.html` shell (music.html clone incl.
  FOUC guard; joins `FOUC_SHELL_FILES`), `app.get('/podcasts')` alias,
  `deriveRouteView` arm, `VIEW_SCRIPT_SRC.podcasts`, `registerView` with
  AbortController-per-init. Nav: `shouldInjectPodcastsNav` gated on
  content (>= 1 subscription incl. ytdlp-toggled ones - probe
  `GET /api/podcasts/health` -> `{ shows, episodes }`), injected into the
  Library anchor chain (order: Music -> Books -> Podcasts -> History),
  `activeNavItem` + href-map entries. Zero subscriptions = byte-identical
  chrome (the disabled-module guarantee, enforced by test).
  Views: show grid (cover cards, `/podcastart/<subId>`) -> episode list
  (newest-first by pubDate; played check, resume bar, download state
  chip) -> add-subscription sheet (URL field + backfill choice + the
  explicit "this URL may contain a private token; it is stored on your
  server only" note). All styles in style.css following the music block
  pattern; every new className grep-verified bound (P10).
- **D10 - playback + per-user state.** Episodes play in the DOCK via
  `player.load(episodeId, {type:'audio', streamSrc:'/episode/<id>',
  progressEndpoint:'/api/podcasts/progress', resumeMode:'podcast',
  artUrl:'/podcastart/<subId>', ...}, {dock:true})` with track-nav wired
  to the episode list (prev/next episode). `resumeMode:'podcast'`
  ALWAYS resumes (P8). Schema v9: `user_podcast_progress` (user_id,
  episode_id, position_seconds, duration_seconds, updated_at) +
  `user_podcast_played` (user_id, episode_id, played_at) - the music
  tables' shape with the watched-latch added; manual mark-played/unplayed
  toggle in the UI; auto-latch at >= 95% position. Both tables: ON DELETE
  CASCADE on users, delete-carrier wired when an episode/sub is deleted
  (P2 law), backup export/restore/validation arms in the SAME commit
  (absent-in-older-bundles legal, the v1.68 posture).
- **D11 - poll loop.** `armPodcastsTimer` mirroring armScanTimer
  (.unref, re-armable, 0 = off), `db.podcasts.settings.pollMinutes`
  default 60. Per-sub sequential check: fetch feed (D6) -> parse (D5) ->
  diff guids against episode records -> enqueue missing per backfill
  policy -> download serially (D7) -> write episode records as each
  lands -> scan-free (the place reads db.podcasts directly; no
  db.metadata involvement, structurally retiring the persist-gate class
  for this feature, the books precedent). Failures: `checkFailures`+
  `backoffUntil` (computeCheckBackoff pattern), lastStatus always
  redacted (D3). Single-flight latch; manual "check now" per sub joins
  the same latch.
- **D12 - the heavy-job gate.** `runExclusive` lives in lib/ytdlp and is
  module-internal state (P6). Rather than importing a possibly-disabled
  module's gate, the server owns a NEW shared heavy-job gate primitive
  (`lib/heavyGate.js`, extracted verbatim from lib/ytdlp/index.js:3431's
  logic) injected into BOTH modules via deps. ytdlp's behavior is
  unchanged (same semantics, same snapshot API - regression-locked by
  the existing ytdlp suite); podcasts enqueues enclosure downloads +
  backfill batches through it. Extraction is its own commit so the gate
  diff is reviewable in isolation.
- **D13 - reconcile + deletion.** On each poll cycle end + on boot: walk
  the podcasts root (skip when root missing - the MOUNT-LOSS GUARD:
  an unmounted root never prunes episode records, the ARCHITECTURE.md
  law); episode records whose file vanished while the root IS present ->
  status back to `deleted-on-disk` (NOT re-downloaded: the guid stays in
  the record map, which IS the archive - "deleted stays gone", ytdlp
  precedent). Per-episode delete in the UI: unlink file (through the
  trash machinery - v1.65: every delete is a recoverable move) + keep
  the record as tombstone + drop per-user rows (P2 carriers).
  Sub delete: keep files on disk (they are Dean's cache), remove sub +
  episode records + per-user rows + secret-store entry; DISCLOSED in the
  confirm dialog ("files stay on disk").
- **D14 - deferred (DISCLOSED, tech-debt entries).** (a) Non-mp3
  enclosures (m4a/opus) download byte-true with their real extension -
  ffmpeg-convert-to-mp3 deferred until a real feed needs it. (b)
  Per-episode `<itunes:image>` art (rare) - show-level cover only this
  wave. (c) OPML import. (d) The ytdlp-toggled shows' episodes keep
  their existing watch-page playback + watch-history state (they are
  db.metadata items); dock-first playback parity for them is a follow-up.
- **D15 - the ytdlp toggle (ruling 1).** ytdlp sub records gain
  `libraryPlace: 'default' | 'podcasts'` (add + patch validation,
  default 'default', ensureYtdlp backfill). The podcasts place lists
  toggled subs as shows; their episodes = db.metadata items under the
  sub's channelDir (P12 join), newest-first by embedded date/mtime,
  played state = existing user_watched/user_progress. The toggle is
  edit-only UI in the EXISTING subscriptions page settings sheet (one
  new select, bound to the base select rule - P10).

## Attack surfaces for the adversarial seat (named)

1. Token leakage: API list/status responses, lastStatus after a fetch
   error (Node error.message embeds URLs!), runlog-style lines, backup
   bundle contents, the secrets file mode/atomicity, client-side echo of
   the add-form URL.
2. SSRF: feed URL -> internal host (literal, DNS, redirect hop, http->
   file:// downgrade attempt, userinfo), enclosure URL from a HOSTILE
   FEED (the feed author controls enclosure URLs - they are UNTRUSTED
   even when the feed URL is trusted).
3. Path escape: show title `../../`, guid with path chars, filename
   collision between episodes, the .ptpart sweep unlinking outside the
   show dir.
4. Parser: 25 MB+ input, 100 K items, nested CDATA, `<!DOCTYPE` + entity
   definitions, guid/title with NUL + control bytes (node:sqlite
   truncates TEXT at NUL - known repo lesson), RTL/zero-width filename
   tricks.
5. Data destruction: kill mid-backfill (partial must vanish, records
   consistent), mount the root away mid-poll (no prune), delete a sub
   (files must SURVIVE), restore an old backup over a newer library,
   schema v9 migration on a v8 db with live per-user rows.
6. The heavyGate extraction: mutation-test that ytdlp still serializes
   through it (delete-the-callsite must fail a test).
