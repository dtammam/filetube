## Intent (Dean's 7 items + intake rulings)

1. **Most watched (Stats) -> sortable table + fill.** Convert renderMostWatched
   to buildSortableTable (Title | Plays, default Plays desc; drop the "N." rank
   prefix - sort IS the rank); add `.stats-table-host` to lift the 240px cap.
2. **Subscriptions Activity redo.** Make Download history, Download failures, AND
   Maintenance three collapsible sections DEFAULT-COLLAPSED, styled like the
   Settings collapsibles (they already use `.setup-box sub-collapsible`). Tucks
   away the janky 5-button maintenance row.
3. **Under the hood (Stats) -> fill only.** Lift the 240px cap so it fills;
   KEEP the current label/value reference rows (mixed-unit metrics - not sorted).
   A fill-only class (NOT `.stats-table-host`, which zeroes padding for a
   `.stable` table).
4. **Top-of-page hidden under the header on IN-APP nav.** ROOT CAUSE (diagnosed):
   `history.scrollRestoration` is never set, so it defaults to `'auto'` - the
   browser restores a remembered scroll position on the pushState nav and
   OVERRIDES swapToView's synchronous `window.scrollTo(0,0)` (common.js:8104).
   Fix: `history.scrollRestoration = 'manual'` at bootRouter (guarded). DEVICE-
   VERIFY (Dean's device is the arbiter; if it persists, re-root-cause - do NOT
   patch around).
5. **Home button -> back to the last page on Stats/Settings/Subscriptions.** The
   Home affordances already walk back via goHomeControl -> resolveHomeButtonAction
   ('back' when depth>0). All three ARE SPA routes (deriveRouteView maps them),
   so depth is tracked. VERIFY it returns to the prior page from each; fix only
   if a real gap (e.g. a page reached by full-load resets depth).
6. **Left-edge swipe-back.** NET-NEW (no swipe gesture exists today). A swipe
   from the LEFT EDGE (start x < ~24px, horizontal-dominant, past a threshold)
   triggers the same back as the Home 'back' action (history.back() when
   depth>0, else no-op - never exit the app). Global on the shell. Excludes:
   the watch page's tap-to-seek zones (edge start is fine - it's a drag not a
   tap, but guard anyway), horizontal sliders/rows (an edge start rarely lands
   on one; ignore if the gesture begins inside a horizontal scroller). Reuses
   the existing history/depth model - no new view stack.
7. **Modern Home card/list toggle.** The `ft-view-mode` (card|list) setting +
   `applyViewMode` ALREADY drive the modern grid, but the `#view-mode-btn` lives
   in `.section-actions` which modern mode HIDES - so no control. Add a view-mode
   toggle into the modern Home's chip/sort chrome (main.js modern render), wired
   to the SAME getStoredViewMode/setStoredViewMode/applyViewMode. Changing it in
   Downloads already persists here; now it's changeable here too.

## Grounding facts (verified)

  (~common.js:8520) seeds depth 0; `buildHistoryState(view,url,scrollY,depth)`;
