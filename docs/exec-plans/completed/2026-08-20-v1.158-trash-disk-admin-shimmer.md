## Intent (Dean's asks, this wave)

- **A - Admin-section nav shimmer (crispness).** On Settings, the Downloads /
  Users / Backup & Restore menu rows "appear in after a second." They start
  `hidden` and setup.js un-hides them after an is-admin capability fetch, which

## Grounding facts (verified in source, this session)

- The master-detail nav (`wireMasterDetail`, common.js) builds `.md-row`
  buttons from `visibleSections()` = NON-hidden `details[data-collapse-key]`
  only. This is the v1.80 privacy protection: a real admin ROW never renders
  for a restricted user. A `MutationObserver` on each section's `hidden`
  attribute calls `buildNav()` on reveal (common.js ~5139).
- The three admin sections (setup.html): `#downloads-box` (group System, badge
  Admin), `#users-box` (group Account, badge Admin), `#backup-box` (group
  Account, badge Admin). All start `hidden` + `data-md-badge="Admin"`.
  setup.js reveals users/backup at `me.user.role === 'admin'` (~1953-1959) and
  downloads after the engine fetch (~2699-2714).
- The shared, memoized `GET /api/auth/me` consumer lives in common.js (~233-
  255) and already gives `user.role`. `accountSignOut` clears per-device flags
  (e.g. `ft-notif-bell-enabled`, ~5632).
- Trash model: `db.trash` = trashId -> record `{ originalId, originalPath,
  trashedAt, rootFolder, item:{title,name,type,ext,size,duration,...} }`.
  - `GET /api/trash` returns `{ items[], total, retentionDays }`, RBAC-filtered
    by the shared `trashRecordVisibleTo(req, rec)` predicate (gate fix: GET, the
    single-purge, restore AND purge-all now all use this ONE predicate, so the
    set a member can list == the set they can destroy); each item has a `size`
    (`(rec.item && rec.item.size) || 0`). (server.js 11728-11762)
  - `DELETE /api/trash/:id` -> `purgeTrashItem(...)` PERMANENTLY destroys the
    file; guarded by `requireModifyLibrary` + `refuseIfReadOnlyMedia` + per-item
    `trashRecordVisibleTo` (server.js 11780-11794).
  - Client: `renderTrashSection` (setup.js ~2280) fetches `/api/trash`, renders
    rows, and already has a two-tap PURGE arm/disarm (3000ms) for per-item.
- Stats "Total size on disk" tile = `statsData.totalSizeBytes` (stats.js 153) =
  `stats.computeLibraryStats(visibleMetadata).totalSizeBytes` (server.js 15225),
  where `visibleMetadata` = `withEffectiveViewCounts(db)` filtered by
  `mediaVisibleTo(req, item)` (15159-15163). Metadata (video+audio) only - NOT
  books/music-store. `computeTotalSize` = reduce over `item.size` (lib/stats.js
  71). Client formats with `formatByteSize`.
- Account menu footer built in `injectAccountMenu` (common.js ~6288-6303): a
  Version row (`.account-menu-version`, an `<a>` link to release notes) after a
  divider. `appVersionString()`/`releaseNotesUrl()` are pure + exported.

## Task plan (small, independently-testable commits)

### T1 - server: trash total + purge-all endpoint (Part B server half)
- `GET /api/trash`: add `totalSizeBytes` = sum of the RETURNED (visible) items'
  `size`. (Single source of truth for the client total + what purge-all frees.)
- `POST /api/trash/purge-all` BEFORE `POST /api/trash/:id/restore` (static-
  before-param safety, though method+shape already disambiguate):
  - `requireModifyLibrary` -> `refuseIfReadOnlyMedia` -> enumerate `db.trash`
    filtered by the SAME visibility predicate as GET (canonical descriptor via
    `trashRecordVisibleTo`), `purgeTrashItem` each, accumulate count + freed
    bytes. Return `{ success, purgedCount, freedBytes }`. A restricted member
    purges ONLY what they can see; an admin (empty index) purges all.
- Tests (integration + unit): purge-all removes exactly the visible set, leaves
  restricted items intact, 403 for a member without modify-library, read-only
  media refused, empty-trash is a harmless no-op, `totalSizeBytes` matches the
  item sum. ADVERSARIAL FOCUS: RBAC bypass (a restricted member must not purge
  or even count a hidden item), partial-failure accounting.

### T2 - client: trash toolbar (Empty-trash two-tap + total) (Part B client half)

  (the "N items - X GB" line) + `#trash-empty-all` button.

- Tests: the count+size line, empty-state hides the toolbar, the two-tap arm

## Attack surfaces to brief the gate (full)

1. **RBAC on purge-all (CRITICAL class, v1.80/v1.81).** A capable-but-
   restricted member must not purge OR count a hidden trash item. Brief the
   adversarial seat to try to destroy another user's restricted media via
   purge-all; demand a runnable repro and mutation-tested guard.
2. **Read-only + capability guards** present and effective on purge-all (mutate
   them red).
3. **Two-tap can't fire on one tap** (fixture/network leak: the first tap must
   NOT hit the network); disarm actually disarms.
4. **Total-size honesty**: `totalSizeBytes` == the purged bytes == the sum the
   client shows; orphans with size 0 are disclosed as best-effort.
5. **You-menu figure == Stats tile** (shared fn, not a re-derivation that can
   drift); fetch-failure hides the row rather than showing a broken value.
6. **Admin shimmer privacy + stranded-shimmer**: a non-admin (incl. a stale
   shared-device flag) never sees an admin LABEL and never strands a shimmer;
   the placeholder clears on BOTH the reveal and the non-admin axes.
