# v1.52.0 - Instant watch (no placeholder flash, no layout shift)

Status: SHIPPED v1.52.0 (docs reset 2026-08-15; see ROADMAP.md). Was: ACTIVE. Owner: main session (lean mode). Reviewers' spec.

## Dean's ask (2026-07-29)

"I see Loading title..., 0 views, no stars, Folder uploader for about a
second when picking a vid on mobile... it just ruins the immersion. It
ultimately isn't the same size. How can we NOT have a FOUC... loads the
content properly in the right sized frame without flash or resize."

## Decisions (probed, all AGREED)

1. Fix everywhere, not mobile-only (same code path).
2. Core approach: seed-from-card synchronous paint - the tapped card's
   in-hand data populates the watch page during the SPA swap; the detail
   fetch hydrates only what cards don't carry and never visibly rewrites
   a painted value.
3. Player frame reserved at the item's real aspect ratio with the
   thumbnail painted immediately (poster) - no resize on stream attach,
   portrait correct from frame one.
4. Cold loads (deep link/refresh/no seed): neutral skeleton shimmer.
   Literal placeholder text ("Loading title...", "10.5K subscribers",
   "0 views", "Folder uploader", "/loading...") never renders again.
5. Mock values compute in frame one from seed data and never change on
   hydration.

## Measured root cause (recon, 2026-07-29 - the promised verification)

THREE serial round trips before the first metadata pixel: (1) navigate()
fetches + DOMParses the whole watch.html document (common.js:4666/:4266);
(2) initWatch awaits /api/config (watch.js:905); (3) then serially awaits
/api/videos/:id (watch.js:912). populateMetadata runs only after all
three. #player-slot is an EMPTY, ZERO-HEIGHT div until player.load at
watch.js:964 - the page's tallest element appears in one jump. The SPA
re-parses a FRESH fragment every navigation, so the static placeholder
literals (watch.html:190/194/245/254/255/271/295...) re-flash on every
watch->watch hop too. Recon also proved: every field populateMetadata
renders is present on the LIST item already in memory at click time
(server returns the full metadata record for lists, no projection), and
stars + comment count need only the media id.

## Architecture

### T1 - seed transport + synchronous pre-paint + placeholder purge

- Module-level single-entry stash in common.js (the homeViewCache
  precedent, common.js:4217): `stashWatchSeed(item, extras)` /
  `consumeWatchSeed(mediaId)`. Consumed on read; rejected unless
  seed.id === the ?v= id; stale after 10s (belt for a stash that never
  got consumed). Exposed on window.FileTube for main.js/watch.js/
  player.js writers. Extras carry folderSettings when the surface has
  them (main.js does).
- Writers (every /watch.html?v= surface, enumerated by recon - the
  v1.41.4 "every writer" discipline):
  - main.js grid/liked cards (delegated click on the grid, before the
    document-level anchor handler bubbles; item via the existing
    currentItems.find precedent, main.js:1325)
  - watch.js related cards + prev/next/navigateToWatch (items in memory)
  - player.js autoplay-next + dock-return (player's own currentData)
  - common.js notification bell rows (PARTIAL seed - the row model
    carries title/channelName/avatarUrl/type/hasThumbnail only; the
    painter paints what is present and skeletons the rest)
- initWatch pre-paint, synchronous, before ANY await: if a seed exists,
  run the populateMetadata equivalent from seed (title, views label,
  channel name + avatar, date, size, ext, file path, description via
  resolveDisplayDescription(tags,title)); stars + mock comment count
  render UNCONDITIONALLY at init (id-only - never data-gated again).
- watch.html placeholder purge: every literal in the recon inventory
  replaced by skeleton-classed empties (title bar, meta line, avatar
  circle, uploader lines, description lines) - the existing
  .skeleton-shimmer system (style.css:1319+, --bg-secondary token,
  reduced-motion carve-out already handled). "Show more" hidden until
  setupDescriptionToggle decides. Related header hidden until rows.
- LOCK test: no forbidden literal ever returns to watch.html's
  #view-root (asserting markup ABSENCE is the honest lock for a flash
  class - there is no runtime to bind).

### T2 - player pre-load + reserved frame + poster

- Seeded path: player.load() is called IMMEDIATELY in the pre-paint with
  seed data + slot (streamUrl derivable; list items carry
  needsTranscode/transcodeStatus/type/width/height). This starts the
  actual video fetch ~2 RTT earlier AND fills the slot in the same
  frame. applyMediaAspect(width,height) already runs before src
  (player.js:5410) - the frame is right-sized from the first paint.
  Hydration must NOT re-call player.load for the same id (the existing
  resolveWatchEntryReparentAction 'adopt' semantics); detail-only extras
  (resolved chapters, transcode/audio progress) apply through the
  existing update seams. GATE MUST VERIFY: no double-load, no
  src re-set, chapters land late without a reload.
- Video poster: setupForMedia sets poster=/thumbnail/<id> for VIDEO when
  hasThumbnail (today only audio gets one, player.js:5468) - kills the
  black frame between mount and first video frame. Teardown already
  strips poster (player.js:5163) - unchanged.
- Cold path frame: #player-slot gets a base CSS rule - when empty,
  a 16/9 (default) skeleton box with the same margins as
  .player-container, so the page NEVER lays out without a reserved
  player area. Cold portrait items adjust when data arrives - accepted,
  disclosed (seeded portrait items are right from frame one).
  CSS CAUTION (v1.40 lesson, style.css:988-995): any wrapper inserted
  for the skeleton must preserve definite-height resolution - flex, not
  plain block.

### T3 - parallel fetches + hydration discipline

- /api/config and /api/videos/:id fetch in PARALLEL (Promise.all) -
  saves one RTT for everyone including cold loads. When the seed carried
  folderSettings, the channel name paints in frame one and config only
  refreshes the sidebar.
- Hydration rule: after the detail fetch, a field is re-written ONLY if
  its rendered value would differ (avatar node especially - the reset
  applier recreates the <img>, a flicker if re-run with the same URL).
  The yt-dlp avatar FALLBACK (detail-only, server.js:8059) is the one
  legitimate upgrade: empty seed avatar -> resolved subscription avatar.
- Error path unchanged (detail 404 still shows the error state - a
  seeded paint for a just-deleted item is superseded by the error).

## Gate round 1 (both seats REQUEST CHANGES; every finding applied)

- C1 (BOTH seats independently): the plan's own writer enumeration named
  player.js autoplay-advance and dock-return, and neither was wired -- the
  v1.41.4 "every writer" class re-striking on the two most passive hops.
  Both now stash (autoplay: the next item's record already in hand;
  dock-return: currentData + id, watch-route only). Autoplay/dock seeds
  carry no folderSettings (the player has none) -- a custom
  folder-display-name mapping can correct at hydration on those two paths.
- C2 (adversarial): the pre-load handed the player RAW `chapters`/
  `chaptersManual` from list data, bypassing the server's
  manual > embedded > description precedence -- junk embedded chapters an
  operator overrode painted for a round trip, and the late apply snapped an
  open menu shut. Both raw sets are now STRIPPED from the pre-load payload;
  applyLateDetail is the only chapters writer on that path. The plan's
  claim "list carries everything except resolved chapters" was wrong the
  dangerous way (it carried the WRONG sets) and is corrected above.
- W1 (adversarial): the hydration error path now stands the pre-loaded
  player down (a playing/erroring video above "file not found" contradicts
  itself) and strips EVERY skeleton, not just the title's.
- W2 (adversarial, mutation-audited): zero tests bound the new wiring --
  deleting the consume/pre-paint/pre-load/late-detail/writer/poster call
  sites failed nothing. Comment-stripped, statement-anchored source locks
  now cover each site, honestly labeled presence-not-binding (no browser
  harness exists); the device probes remain the behavior gate.
- W3 (adversarial, disclosed below): stale list data (cached home + a
  reheat landing elsewhere) can paint values hydration then corrects.
- QA W2/W3: two comments claiming bindings that don't exist (autoplay via
  navigateToWatch; seed progress driving resume) corrected.
- QA S4: the main.js isConnected guard had no reachable false branch for a
  real click (the v1.49 dead-guard class) -- dropped, with the reasoning in
  its comment. QA S5: the tautological determinism assert replaced with a
  real list-shape vs detail-shape plan comparison. ADV S1: the empty-slot
  reservation scoped to `.watch-container` (the v1.50.5 same-slot-id
  lesson, pre-empted). ADV S2: stale poster-audio-only comment fixed.

## Gate round 2 (QA APPROVED the round-1 delta; adversarial REQUEST
## CHANGES with two new findings on the fixes themselves; both applied)

- W-A (the fix-round-fix-regresses class): round 1's error-path close()
  could fire from a DEAD view -- the hydration fetches carried no abort
  signal, so navigate-away left the continuation alive and a late failure
  closed whatever was playing NOW (the dock, or a re-opened full player).
  Both fetches now carry the view signal and the catch begins with the
  aborted-staleness guard (the file's own prev/next idiom).
- W-B: watch->watch hops resolve 'reparent', not 'defer', so the seed
  painted video B's metadata while video A kept PLAYING under it until
  hydration (title/audio mismatch; a pause tap in the window hit A). The
  reviewer's preferred fix taken: a full seed now pre-loads on 'reparent'
  too (the seed IS the requested video, voiding the keep-alive rationale),
  and the eager expand is skipped when the pre-load supersedes it.
  RESIDUAL (round-2 S3, disclosed in known-gaps): a PARTIAL seed (a bell
  row) on a reparent hop cannot pre-load, so that narrow case still
  paints B's title over A until hydration - the right trade (a partial
  seed cannot start B; killing A would leave a dead frame).
- S-C: the round-1 commit had silently failed in a background compound and
  the whole round swept into a commit titled as a browseCtx tweak --
  amended (unpushed) to describe its true content honestly.

## Known gaps / accepted residuals

- Cold-load portrait items: frame corrects 16/9 -> portrait when data
  arrives (only the no-seed path; disclosed).
- The full-document fetch+DOMParse per SPA nav (recon step 1-2) is
  untouched this wave - a view-fragment cache is a future optimization;
  seeded paint makes it invisible for metadata purposes.
- Detail-only fields (Share button's watchUrl, resolved chapters,
  transcode %) still arrive at hydration - they are controls, not
  above-the-fold content, and never move layout (gate to verify the
  Share/theatre buttons don't shift the action row when they appear).
- (Gate round 1, ADV W3) A STALE seed can paint values hydration then
  corrects: home is cached, so a reheat/rename landing while elsewhere
  means the tapped card's data is old -- title/views repaint with the
  fresh value one round trip later (text swap, no layout shift; the 10s
  age gate bounds stash-to-consume, not data age). Same-frame-correct on
  fresh data, self-correcting on stale; accepted and disclosed.
- (Gate round 2, ADV S3) A PARTIAL (bell-row) seed on a watch->watch hop
  where another video is still playing paints the new title over the old
  audio until hydration -- a partial seed cannot pre-load (no stream
  fields), and killing the old video would leave a dead frame. Narrow
  (bell tap while a video is FULL on the watch page); accepted.
