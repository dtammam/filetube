## Scope (Dean: "proceed" + "include it in CONTRIBUTING so any new thing does this")

1. **The standing CONTRACT (CONTRIBUTING).** A new MANDATORY convention beside the
   design-token rules: every surface that renders from data fetched AFTER first
   paint MUST ship a reserved-space skeleton-shimmer that reveals ONCE (seed
   before the await; the real `innerHTML=` on resolve is the reveal; clear on
   error; zero-shift by reusing the real box). "Blank-then-pop / a bare spinner /
   a reflow-as-data-lands" is a review finding, like an ungoverned literal is.

2. **Avatar-bar flicker (Dean's device report on v1.98).** The top chip-row "flow"
   flickers / gains-or-loses a row: root cause is the MOBILE avatar bar
   (`#modern-avatar-bar`, main.js:1351) that ships `hidden`, then `/api/channels`
   resolves and it POPS IN above the chips, shifting them down (variable
   recent-uploader count = the "more or less"). FIX: persist the last-known
   channel count in localStorage; on load, if >0, seed the strip with N shimmer
   avatar chips + un-hide it (reserve the space), and populateModernAvatarBar
   reveals the real chips (or collapses if now truly none) - the v1.53
   capability-cache / seed-from-last-known pattern. First-ever load has no cache
   (one-time pop-in, disclosed).

3. **Watch RELATED rail** (audit row 15). `loadRelatedFiles` fetches
   `/api/videos` then fills `#related-files-container` - blank rail until resolve.
   FIX: seed `.related-card`-shaped skeleton rows + reveal the header before the
   fetch; the existing `innerHTML=` (real cards / "No other files" / error) is the
   reveal. (`.related-thumb` is `#000` letterbox - restore `--bg-secondary` on the
   skeleton variant, the v1.98 art-box pattern.)

## Gate findings (round 1) + fixes

QA APPROVE, adversarial REQUEST CHANGES - converging on the avatar-bar edges.

- **WARNING (QA) - the reveal was ~4px NON-zero-shift + the "zero-shift" comment/
  test overclaimed (presence-not-binding).** The skeleton label was 10px but the
  real `.modern-avatar-name` is `--fs-2xs` (10px) x 1.4 = a 14px line box -> a 4px
  settle. FIXED: skeleton line -> 14px (chip = 56+4+14 = 74px = real); the test now

- **WARNING (adversarial) - N->0 reverse-COLLAPSE.** localStorage is per-DEVICE, so
  a second user (or an unsubscribe-all) can read a stale count, reserve a strip,
  then collapse it to hidden when their real `/api/channels` returns 0 - an upward
  jerk. MITIGATED: `accountSignOut` now drops `ft-modern-avatarbar-count`, so a
  clean logout->login user switch (the common multi-user flow) starts fresh.
  DISCLOSED RESIDUAL (below) for the paths that skip logout.
- **SUGGESTION (both) - the new CONTRIBUTING strand clause overclaimed "aborted
  view clears".** The reference impls rely on SPA teardown. FIXED: the clause now
  says DATA exits clear; an aborted view may rely on teardown WHEN the host is
  rebuilt on re-entry, else clear on abort.
- **SUGGESTION (adversarial) - buildRelatedSkeletonCards guard test-unbound.**
  FIXED: added negative / non-integer assertions.

### Disclosed residuals (ship-with, symmetric to the first-load pop-in)
- FIRST-ever load on a device: no cache -> the bar still pops in once (the seed
  needs a prior visit to know the count).
- N->0 reverse-COLLAPSE without a logout: if a user switches browsers/tabs WITHOUT
  signing out (so the logout-clear never ran), or unsubscribes from everything, or
  hits a `/api/channels` error with a warm cache, the reserved strip collapses once
  (~one avatar-row upward). One-time, cosmetic, strictly smaller than the pop-in it
  replaces; revisit trigger = Dean reports a downward jerk after a user switch.

## Adversarial attack surfaces (brief)
- Avatar-bar skeleton STRANDS (fetch error/abort leaves shimmer), or REVERSE-
  shifts (cache said N, real is 0 -> collapse jump), or the cache write/read
  desyncs across users/devices. Related skeleton strands on error/empty/abort or
  shifts on reveal (thumb/line box mismatch). CONTRIBUTING rule is accurate.
