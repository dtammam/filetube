## Design

### Asset (server, scan time)

`extractStoryboard(filePath, mediaId, duration)` - one ffmpeg pass, no shell
(`execFile`/`spawn` with an argv array, matching the injection-hardened
thumbnail extractor):

- Planner (PURE, unit-tested) `planStoryboard(duration)`:
  - `TILE_W = 160`. `TARGET_FRAMES = 40`, `MIN_FRAMES = 10`, `MAX_FRAMES = 100`.
  - `interval = clamp(duration / TARGET_FRAMES, MIN_INTERVAL=2, MAX_INTERVAL=10)`
  - `count = clamp(floor(duration / interval) + 1, MIN_FRAMES, MAX_FRAMES)`
    (re-derive interval = duration / count so spacing is exact and even)
  - `cols = min(10, count)`, `rows = ceil(count / cols)`
  - Returns `{ v:1, interval, count, cols, rows, tileW: TILE_W }`.
  - Very short clips (< ~2s) or 0-duration -> return null (no storyboard;
    the single poster thumbnail already covers them).
- Arg builder (PURE, unit-tested) `buildStoryboardArgs(filePath, outPath, plan)`
  -> `['-ss','0','-i',filePath,'-vf',
       'fps=1/${interval},scale=160:-2,tile=${cols}x${rows}',
       '-frames:v','1','-q:v','4','-y',outPath]`.
  (`scale=160:-2` keeps even height for the encoder; tileH is discovered from
  the produced sprite's pixel height / rows and NOT trusted from source dims,
  so mixed-aspect libraries stay correct. Descriptor stores the real `tileH`.)
- Output: `THUMBNAIL_DIR/<mediaId>.sb.jpg`. Descriptor `{v,interval,count,cols,
  rows,tileW,tileH}` persisted on `item.storyboard` (see persist-gate above).
- Generation is best-effort: any ffmpeg failure -> `storyboard: null`, feature
  simply absent for that item. Never blocks the scan or the single thumbnail.

### Serving

`GET /storyboard/:id` - mirror `/thumbnail/:id`:
- Same RBAC 404 guard as `/video/:id` and `/thumbnail/:id`.
- Serve `<id>.sb.jpg` with `Cache-Control: private, max-age=86400`; 404 if absent
  (client degrades to no-preview).
- **Route order**: register the static-segment `/storyboard/:id` with the other
  static routes, before any `/:id` catch-alls (Express route-order norm).
- Geometry travels in the API item projection (`item.storyboard`), so no
  separate descriptor route and no per-card sidecar read.

### Client - scrub preview (`player.js`)

- A `#seek-preview` element positioned above `#seek-bar`.
- PURE reducers (unit-tested, no DOM):
  - `frameIndexForTime(t, geom, duration)` = `clamp(floor(t/interval), 0,
    count-1)`.
  - `spriteTile(index, geom)` -> `{ bgPosX, bgPosY, bgSizeW, bgSizeH }` for the
    CSS `background-position`/`background-size` into the sprite grid.
- `pointermove` over the bar -> reuse `scrubRatioFromPointer()` -> t -> set the
  preview's background + position it horizontally at the pointer + a timestamp
  label. `pointerleave` hides it. Works during touch-drag scrub (reuses the
  existing pointer-capture handlers) so mobile gets it too.
- Only wire when `data.storyboard` is present.

### Client - card preview (`main.js` + `style.css`)

- Overlay `<div class="card-preview">` on `.thumbnail-img`, `background-image`
  = `/storyboard/<id>`, sized to one tile, `background-position` cycled 0..count-1
  on a timer. Show via class, hide -> reset to the static poster.
- **Desktop**: `pointerenter` starts the cycle, `pointerleave` stops+resets.
- **Mobile / in-view autoplay**: one shared `IntersectionObserver` (threshold
  band around viewport center). The most-visible card in the band cycles;
  leaving the band stops it. Cap concurrent animations (target: 1-2) to protect
  battery and avoid a wall of motion.
- **Guards**:
  - `prefers-reduced-motion: reduce` -> no cycling at all (static poster).
  - Only create the overlay/observer for cards whose item has `storyboard`.
  - Teardown: intervals + observer disconnect on view swap. The home grid lives
    inside `#view-root` (swapped by the SPA) so the view abort signal applies -
    but VERIFY against the v1.85 "cached home view doesn't abort" scar; if the
    home view is cached, route-bind teardown to `body[data-view]` change instead
    of relying on an abort that never fires.
