## The reusable component (T1) - `buildSortableTable`

A vanilla-JS component (in common.js, exported; CSS in style.css per the SPA
rule - view styles never in a shell `<head>`). Signature (final shape TBD in
code, but):

    buildSortableTable(host, {
      columns: [{ key, label, align, numeric, format(row), sortValue(row) }],
      rows,                       // array of plain data objects
      actions,                    // optional (row) -> Node for a trailing non-sortable cell
      filter: { keys, placeholder },  // name-search; keys the query matches against
      defaultSort: { key, dir },      // dir: 'asc' | 'desc'
      persistKey,                 // localStorage key -> remembers {key,dir} per table
      caption,                    // a11y
    })

Behaviour, all bound by tests:
- Renders a header row of tappable column buttons (`<button>` in a header cell)
  + a filter input above the body. Clicking a header sorts by that column;
  clicking the ACTIVE header flips dir. `aria-sort` on the active header;
  a caret glyph marks it. Numeric columns sort by `sortValue` (raw number),
  text by locale-compare; STABLE sort (ties keep input order).
- The filter narrows rows by substring match against `filter.keys` (case-fold),
  live on input. Empty query = all rows. An empty result shows a friendly
  "No matches" row, not a blank table.
- Persistence: the chosen {key,dir} is saved to `persistKey` and restored next
  open (the Books precedent); a first-ever open uses `defaultSort`.
- PURE CORE extracted + unit-tested: `sortRows(rows, col, dir)` and
  `filterRows(rows, keys, query)` (deterministic, no DOM). The DOM wiring is
  jsdom-mounted (header click -> reorders; flip; filter narrows; persistence
  round-trips; empty-state). Mutation-bind the flip and the numeric-vs-text
  branch (the "presence not binding" class).
- MOBILE-FIRST: the name column flexes + truncates (ellipsis), the numeric
  columns are narrow + right-aligned + `tabular-nums`, the header labels stay on
  ONE row at 360px (the screenshot's width). Measure, don't guess (the repo
  lesson) - a numeric header must not wrap. Design-token census stays 0.

  for the requester's visible metadata (built exactly like /api/stats scopes -

  + bump the route-count pin. Client sorts/filters the full set; render is a
  HARD CAP (component `renderCap`, AV=300) of the CURRENT sort/filter + an honest

  never mounts thousands of nodes. SHIPPED as the hard cap, NOT lazy
  append-on-scroll (simpler; every item stays reachable via sort asc/desc + the
  title filter - the truncation is disclosed, never silent). JUDGMENT CALL (Dean
  can override): a lean all-items payload
  + client sort, not a server-paginated sort, so every column sorts instantly
  without refetch; ~60-100 B/item keeps even a 5k library well under 0.5 MB.
- **T6 - Settings Users.** Columns: Name | Role | Subscriptions | Modify |
  Status, + a trailing ACTIONS cell (the existing per-row buttons, non-sortable).
  Sort by name/role/status; filter by name. MUST NOT change any RBAC gate or

- **T7 - Settings Trash.** Columns: Title | Size | Trashed (days-left), +
  actions (Restore + the two-tap Purge). Sort by size/date/title; filter by
  title. Integrates with the v1.158 toolbar (total + two-tap Empty) untouched.
- **T8 - Music tracklist. DEFERRED (disclosed, tech-debt) - the flagged risk hit.**

  Not a layout swap; a deliberate follow-up where the sort-vs-play-order
  semantics get designed. Logged in tech-debt-tracker.md. The other SEVEN
  surfaces (T1-T7) deliver the ask.
