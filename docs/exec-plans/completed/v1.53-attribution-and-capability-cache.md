# v1.53.0 - Manual channel attribution + capability cache

Status: ACTIVE. Reviewers' spec. Two independent tracks, one wave
(Dean-approved). FULL gate - track A can MOVE ~200 user files.

## Dean's asks (2026-07-29)

A. "Attribute a specific video that doesn't have metadata of a channel
(renamed/dead link) to another... I hate seeing not attributed YouTube
content under the yt-dlp folder." ~200 files, MeTube-era.
B. Reheat/Subscribed/pinned take a beat to appear on refresh - close it
with a cache. "As long as we don't lean on a serviceworker."

## Decisions (probed, all AGREED)

1. Attribution targets: subscriptions + existing attributed channel
   groups, one picker. No free-text pseudo-channels this wave.
2. Attributing offers the physical move (explicit confirm per item).
3. Manual wins FOREVER, and a reheat that resolves a CONFLICTING real
   identity surfaces a SPECIFIC signal (Dean: "so it's known if it ever
   changes") - never a silent keep, never a silent overwrite.
4. Bulk per-folder path is in scope (~200 files).
5. Capability cache: sessionStorage, stale-button window accepted, NO
   service worker (recon: unregisterStaleServiceWorkers actively sheds
   SWs by policy - the constraint is already load-bearing in code).

- Channel-identity writers census (all in server.js): three consume
  sites (4487/4524/4545 - unconditional), folder backfill (guard
  `!item.channelUrl` at 4601 - safe by construction but gets the

- The attribution predicate everywhere is `item.channelUrl` empty =
  unattributed (common.js:498, server.js:4601, server.js:10073). Never

- Bulk button on ?root= views joins #sub-repull-channel-btn's row: MUST
  carry `order: 12` in the <=768px block (v1.50.4 orphan-row lesson;
  existing bands: watch-toggle 10, repull 11) + title/aria-label
  (btn-label is display:none on phones).
- New-field lifecycle for channelAttributedManually: re-init carry
  (~server.js:4130, seventh-strike checkpoint), Phase-2 mirror following
  the chaptersManual UNCONDITIONAL-including-deletion pattern
  (4374-4383) WITH marker-gated adoption of the five identity fields
  (flag and identity must never desynchronize), mergeScannedMetadata/

- Three health-probe latches exist (watch.js:588, common.js:7769, the

## Track A - manual attribution

### Server
- `GET /api/attribution-targets`: union of (a) subscriptions (id,
  channelUrl, name, channelId?, channelAvatarUrl?, channelDir) and (b)
  distinct identity groups from db.metadata items carrying channelUrl
  (canonical-URL-deduped; name/avatar from first carrier; covers dead
  channels whose earlier downloads were attributed at capture time).
  Sorted by name. Read-only over the cache.
- `POST /api/videos/:id/attribute-channel`: body `{target: {channelUrl,
  channelName, channelId?, channelHandleUrl?, channelAvatarUrl?}}` or
  `{clear: true}`. channelUrl re-validated server-side
  (url.validateChannelUrl); name control-stripped/capped (the store's
  sanitize posture). Writes the identity as a UNIT +
  `channelAttributedManually: true` via the chapters-endpoint
  updateDatabase template; `clear` deletes the flag AND the five
  identity fields (back to genuinely unattributed). Response includes a
  relocation PROPOSAL: `{destinationDir, alreadyThere: bool}` from
  resolveChannelDirForChannel (no file touched here - the move is the
  existing move endpoint, invoked by the client after its own confirm).
- Manual-wins enforcement: the three consume sites wrap their identity
  blocks in `if (!item.channelAttributedManually)` (as a UNIT); the
  backfill call gains `&& !item.channelAttributedManually`; the reheat's
  same-channel gap-fill branch bails for manual items; conflict
  detection at the attributable line reports through a new out-field ->
  runSingleItemReheat writes `attributionConflict: {kept, discovered}`
  on the one-shot (AND resets it in the `running` write - the
  setOneShot MERGE hazard at index.js:1305-1313).
- Bulk: `POST /api/videos/attribute-channel-bulk` body `{root, target,
  relocate: bool}`. Identity for every item under root with empty
  channelUrl (manual flag set) in ONE mutator; when relocate, a
  BACKGROUND two-pass mover (the migrateOneOffsIntoChannelFolders
  template: per-item moveItemToFolder, 409 collisions counted separately
  from errors, summary one-shot via the repull-metadata 202+latch+cancel
  shape). Response: 202 {started, matched} or 200 {attributed, ...} when
  relocate=false. DB SNAPSHOT passed through the loop (the ~11s
  per-item-loadDatabase freeze scar, server.js:10012-10020).

### Client
- Watch page: "Attribute..." button in the action cluster, visible only
  when `resolveFileChannelIdentity(mediaData) === null` (unattributed) -
  structurally absent otherwise. Opens a picker modal
  (createElement/textContent; the subscribe-modal pattern) listing
  attribution-targets with avatars. Confirm -> POST -> repaint uploader
  panel + toast; when the proposal says a move is possible, chain the
  existing confirm-modal -> POST /api/videos/:id/move -> navigate to
  newId (the offerRelocation result handling as template, incl. the
  :not(.modal-closing) guard and player close-before-move).
- Folder view (?root=): "Attribute folder..." button (order 12) shown
  when the view has >=1 unattributed item; picker + a relocate checkbox;
  posts bulk; toast + point at the activity chip for the background move.
- Reheat conflict toast: describeReheat gains the branch AHEAD of the
  parts list: "Kept your manual attribution (<kept>); the source now
  reports (<discovered>)."

## Track B - capability cache (sessionStorage)

- One key `ft-cap-cache-v1`, JSON `{ts, moduleEnabled, subs: [{id,
  channelUrl, channelDir?, name}], pins: [{id, channelDir,
  pinSource, label?, channelAvatarUrl?}]}`. TTL 5 minutes. Every read
  try/catch-wrapped with shape allowlisting (untrusted string - the
  main.js:1022 posture); every write best-effort.
- Writers: the health probes (all three latches funnel through one
  readCapabilityCache/writeCapabilityCache pair in common.js), the
  /api/subscriptions fetch in setupSubscribeButton, fetchAllPins.
- Readers (optimistic render, then reconcile): probeReheatModule and
  probeAndReconcileRepullButton seed their latches from cache;
  setupSubscribeButton/setupPinButton render from cached
  moduleEnabled+subs/pins immediately, then their existing fetches run
  and re-render (both already rebuild wholesale - reconciliation is
  free); renderPinnedSidebar paints from cached pins at init, replaced
  when fetchAllPins resolves.
- Stale window disclosed: a just-revoked capability can show its control
  until the reconcile lands (~1 RTT). Accepted by Dean explicitly.
- NO service worker; sessionStorage (per-tab) not localStorage - a
  revoked module doesn't haunt other profiles/devices, and tab death
  clears it.

## Gate round 1 (both seats REQUEST CHANGES; every finding applied)

The adversarial seat ran its data-destruction brief with runnable repros
and found the wave unshippable as built; QA independently caught a dead
affordance on the headline case. All applied:

- ADV C1 (repro'd): the picker never called openOverlay -- opacity 0, an
  INVISIBLE full-viewport click-eater whose invisible rows could fire a
  blind bulk move (the v1.50.3 class one level up: a shared CSS class
  never implies the sibling's JS REVEAL). Fixed + lock-tested; teardown
  animates through closeOverlayThen; a dismiss handle (W6) dies with the
  view via the abort signal.
- ADV C2 (repro'd -- the reviewer's fixture library was swept and
  FLATTENED into one channel folder, unrecoverably): the bulk selector
  root is now CONFINED to at-or-under a configured library root
  (resolve+sep, the computeMoveTarget posture), trailing separators
  normalized (S3). 400 otherwise.
- ADV C3: the 200-file irreversible op now has all four ceremonies the
  1-file path had: a write-free PREVIEW (server-computed counts +
  destination), a count-naming CONFIRM before anything moves, a
  SINGLE-FLIGHT latch (409 on a second run), and a cooperative CANCEL
  endpoint checked between items ("stop", never "undo"; the resume
  selector finishes the rest on a re-run).
- ADV W1: the mover's results are now reported to a human -- the folder
  view polls the one-shot itself and toasts moved / already-in-place /
  collisions / failed / cancelled (the chip structurally cannot render
  this job's kind; the old toast pointed at it anyway).
- ADV W2: re-runs RESUME -- items already manually attributed to the
  target but not yet in its folder join the move set; already-in-place
  items count as such, never phantom failures (S4).
- ADV W3: the BATCH reheat now counts + logs kept-but-conflicting manual
  attributions (attributionConflicts on the batch one-shot) -- decision
  3's "never silent" holds on both paths.
- ADV W4: per-user pins no longer leak across a same-tab user change --
  the cache key clears on logout AND on every successful login (the
  crash-logout cover).
- ADV W5 (13/19 mutants survived): consume-lane guards (M2/M3/M5) now
  integration-bound; the Phase-2 adopt/clear arms bound by a ported
  version of the reviewer's own mid-scan repro (end-state assertions
  unconditional, arm coverage honestly reported); the conflict plumbing
  (M14/15/16) runtime-bound through the repull-item harness incl. the
  reset-on-next-run; relocateSkipped (M17) bound. M1 (backfill guard)
  remains defense-in-depth by construction and M8 (re-init flag carry) is

- ADV S1: the conflict toast PREPENDS the diff parts instead of
  swallowing the same run's real updates. S2/QA-S1: read-only media now

## Gate round 2 (adversarial re-audit: binding honesty)

The re-audit disproved several round-1 binding claims ("a test named

  the standalone avatar write is reached; the kept-avatar assert kills

  runtime-bound through the batch endpoint harness.

  ({cancelled:false, running:false}); the LOOP's between-items check is
  NOT deterministically bindable without an artificial per-item delay
  hook -- documented here as unbound, verified by reading, and the fs
  layer's exclusive-create bounds the worst case to extra moves the
  resume/re-run model already tolerates.
- HONEST RE-CLASSIFICATION: M7 (Phase-2 adopt-arm identity copy) is
  MASKED by the pre-existing v1.41.5 gap-fill, exactly like the
  documented M8; M15 (running-write conflict reset) is MASKED by the
  terminal stamp for any test that inspects only terminal state. Both
  are correct-by-reading, mutually-masked, and documented rather than
  fake-bound -- round 1's claim that they were bound was wrong.

## Gate round 3 (the M5 binding, third pass)

The adversarial seat's round-3 verification killed everything except M5
and traced the root cause to the DIVERGENT-FIXTURE class (v1.41.9): both
avatar fixtures used `channelThumbnail` -- the RAW capture-input field
name that only `sanitizeCapturedChannelMeta` maps to the persisted
`channelAvatarUrl` -- while the tests seed persisted entries directly, so
`consumeDownloadChannelMeta` never returned an avatar and the kept-avatar
asserts passed vacuously in BOTH lanes. Fixed: one word, twice
(`channelAvatarUrl:` in the bbbbbbbbbbb and ccccccccccc fixtures), with
the reviewer's demanded proof recorded in the round-3 confirm: the M5
mutant (guard stripped) now fails the suite; baseline stays green. The
seat also disclosed its own round-2 grep had hit the Node-reporter trap
this repo's memory warns about -- both sides' claims now carry `# fail`
lines, not test names.

## Known gaps / accepted residuals

- Manual attribution without a youtubeId cannot ride the download
  archive: a moved file is not archived (honest toast already exists);
  dead-link videos are no longer in any feed, so re-download risk is
  nil in the motivating case.
- Attribution targets require an existing identity carrier
  (subscription or previously-attributed items) - a channel FileTube
  has never seen needs a subscription first. Free-text is deferred.
- The capability cache's stale window (~1 RTT) - accepted, disclosed.
