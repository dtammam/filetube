## Scope

### 1. Watched-state filter on the home library

A new segmented control `All | New | Watching | Watched` in the home
sticky bar, sibling of the existing `All | Videos | Audio` format toggle
(which stays exactly as it is - Dean considered multi-select chips and we
agreed segmented-with-All is better: no dead states, one tap to any view).

- **Server-side filtering** (pagination is server-side, so a client-only
  filter would be wrong across pages): `GET /api/videos` gains
  `?watch=all|new|watching|watched` (default `all`). Invalid values fall
  back to `all`.
- **State definitions** (per-user):
  - `watched`: the user has a sticky completion latch for the item, OR
    current progress >= 90% of duration (`WATCHED_PCT = 90`).
  - `watching`: not watched AND progressPercent > 0.5 (the same threshold
    the home grid already uses to show the red progress bar).
  - `new`: neither of the above (no meaningful progress).
- **The completion latch (autoplay/loop mindfulness, Dean's flag):**
  computing "watched" live from current progress would let a looping video
  cycle its timestamp back to ~0 and un-watch itself, and a rewatch-from-
  start would do the same. So: a new SQLite table `user_watched(user_id,
  media_id, completed_at)`; `POST /api/progress` sets the latch the first
  time a write crosses >= 90% (checked on the POST itself, not the
  coalesced flush - it is a rare one-time event and must not be lost to
  coalescing). The latch is never cleared by playback. Autoplay chains
  will latch each video that genuinely plays to the end; disclosed as
  inherent ("played to completion = watched").
- **Pure filter function** in `lib/videoQuery.js` (alongside
  `filterByFormat`): `filterByWatchState(items, watchParam, progressMap,
  watchedSet)` - unit-testable without a server.
- **Frontend:** new segmented group rendered next to the format toggle,
  same component family/geometry (`.format-toggle` classes reused or
  extended), persisted device-locally in `localStorage['filetube_watch']`
  mirroring the format-filter pattern, sent as `?watch=`. On mobile the
  sticky bar is already tight: the watched group may wrap to a second
  compact row; verify no sticky-bar overflow (era-row-overflow test class).
- Items in API responses additionally carry `watchState:
  'new'|'watching'|'watched'` so the client never re-derives thresholds.

### 2. Era-aware player skins

The custom player controls currently ship one hardcoded blocky skin
(border-radius 0, outset bevels) that fits the 2005 era. Re-skin per era
under the existing `data-theme` system, **keeping the control set,
geometry, and spacing identical** (40px desktop bar, 80px two-row mobile
FULL, 26px docked): only visual treatment changes.

- `2005`: today's look, unchanged (base rules stay as the 2005 skin).
- `2009`: glossy-gradient button chrome matching the existing 2009 site
  flourishes.
- `2014`: flat dark strip, no bevels, square corners, red progress fill.
- `2021`: flat + rounded + crisp - pill/round hover treatment on buttons,
  round slider thumbs, thin red seek bar, subtle borders.
- All skins must render correctly in BOTH `data-mode` light and dark
  (the era token system is two-axis; per-era dark overrides exist).
- No new user setting: the player follows the Settings era pick like the
  rest of the UI. No geometry/layout changes - zero risk to the hard-won
  mobile control layout.
- Reference: real YouTube player chrome of each era (research before
  styling).

### 3. Duplicated home toolbar row (bug fix)

Root cause found: `renderFormatToggle()` (common.js ~1345) de-dupes via
`document.getElementById('library-format-toggle')`, which cannot see the
DETACHED cached home view (`homeViewCache` skips destroy). A background
library refresh while off Home (e.g. a download finishing fires the still-
registered `__filetubeRefreshLibrary` against the cached instance) appends
a second toggle to the detached node; returning to Home reattaches it
doubled, until hard refresh. `renderItemCountBadge` (~1179) has the same
latent bug, and both also have the inverse hazard (detached refresh
REMOVING the live row when a live Home is mounted).

Fix: scope the de-dupe lookup to the passed-in container
(`actionsEl.querySelector(...)`) in both functions. The new watched
toggle (item 1) must be born with the scoped pattern.

### 4. Reheat pushed the mobile action row down

Reheat became the 6th button in `.watch-action-btns`; on phones the
glyph-only rule was no longer enough and the row wraps. Dean's pick: hide
the cosmetic numeric rating ("4 / 5") next to the stars on mobile only
(<= 768px), keep the stars, keep the number on desktop.

### 5. Keyboard shortcuts for the Resume prompt

`R` = Resume, `S` = Start from beginning, active ONLY while
`#resume-overlay` is visible. Own scoped handler (the main FULL-only
shortcut switch early-returns when a BUTTON has focus, which is the state
after the overlay renders). Standard typing-context guards. No Escape
binding (dismiss is ambiguous between the two choices). Added to
`KEYBOARD_SHORTCUT_GROUPS` so the `?` help lists them, and to the
keyboard-shortcuts test inventory.

### 6. Phone landscape, not fullscreen: bound the player

Today landscape non-fullscreen has NO height cap (portrait caps are
orientation-scoped): 16:9 at full viewport width + control strip
overflows the screen. Changes:

- Cap the player in `@media (max-width: 768px) and (orientation:
  landscape)` so picture + control strip fit the viewport height under
  the mobile header; video letterboxes (object-fit: contain already
  applies via width/height 100% semantics - verify).
- Add a "media must be playing" guard to the rotate-to-landscape
  auto-fullscreen (player.js onOrientationChange): today it fires even
  when paused/idle, which fights the bounded-layout behavior Dean wants
  when he rotates a non-playing page. Rotating while PLAYING keeps the
  current auto-fullscreen. The no-auto-exit-on-portrait iOS behavior is
  untouched.

## Risks

1. **The latch writes on a hot path** (`POST /api/progress` fires ~every
   4s during playback). Mitigate: only write when crossing the threshold
   and the latch is not already set (read-through set/cache like
   likedSet).
2. **Filter + pagination interaction**: watch filtering must happen
   before pagination and after format filtering, with a single
   per-user progress fetch per request (no N+1).
3. **Era CSS regressions on the mobile control layout** - the layout has
   a long trap history. Mitigate: skins change colors/gradients/radius
   only; any rule touching height/padding/flex of the bar is a finding.
4. **Sticky-bar overflow on mobile** with a second toggle group -
   explicit test + on-device probe.
5. **Detached-cache refresh path** (item 3) is subtle; the fix must work
   for BOTH duplicate-append and live-row-removal hazards.
