# v1.101.0 - Shimmer sweep tranche 3: the persistent header-right cluster

Status: SHIPPED v1.101.0 (docs reset 2026-08-15; see ROADMAP.md). Was: ACTIVE. Branch `release/v1.101.0`. Third FOUC-sweep tranche (audit:
`docs/exec-plans/active/fouc-shimmer-audit.md`, rows 3 + the bell).

## Problem

`.header-right` ships EMPTY; the account menu (injectAccountMenu, after
/api/auth/me) and the notification bell (injectNotificationBellIfEnabled, after a
/api/notifications/badge probe) are JS-injected AFTER their fetches - so the
top-right of EVERY full page load pops a control cluster in a beat late. On MOBILE
the account trigger is `display:none` (account is the You tab), so the mobile
pop-in is the BELL; on desktop it's both.

## Fix - reveal-once, per control (the v1.99 avatar-bar pattern)

- **Account avatar** (always present when signed-in): injectAccountMenu now
  RESERVES a `#account-menu-placeholder` (a `.account-menu-trigger` wrapping a
  `.account-avatar.skeleton-shimmer` 32px disc) synchronously BEFORE the fetch,
  and removes it on resolve (signed-in -> real menu; signed-out / error -> gone,
  never stranded). Reuses the real box (zero-shift) and inherits the same mobile
  `.account-menu-trigger { display:none }` hide, so it's desktop-only exactly like
  the real trigger. No persist needed (injectAccountMenu only runs on app shells,
  which are signed-in; the placeholder clears on a 401).
- **Notification bell** (feature-probe gated, so conditional): PERSIST the
  last-known-enabled flag (`ft-notif-bell-enabled`, localStorage - the avatar-bar
  pattern). If enabled last time, reserve a `#notif-bell-placeholder`
  (`.notif-bell-btn` wrapping a 22px `.notif-bell-skel.skeleton-shimmer` disc,
  matching the real 22px bell svg) before the probe; the probe reconciles (enabled
  -> real bell + persist 1; disabled -> remove placeholder + persist 0). The
  fail-closed catch removes the placeholder too. Per-DEVICE, so BOTH header
  reserve keys (bell + avatar-bar) are dropped on accountSignOut so the next user
  on a shared browser doesn't inherit them.

## Disclosed residuals (symmetric to v1.99's avatar-bar)
- FIRST-ever load on a device: no bell flag -> the bell still pops in once.
- Bell N->0 (feature turned OFF since, or a shared-browser user whose instance has
  it disabled after sign-out clears the flag - so only the same-instance
  disable): a one-time placeholder collapse. Rare (the feature is stable
  per-instance); the sign-out clear removes the shared-browser case.

## Gate findings (round 1) - both seats APPROVE

QA APPROVE, adversarial APPROVE (it built its own behavioural bell harness -
strand/orphan-free across 6 badge outcomes - and mutation-killed all 5 tests).
Two non-blocking SUGGESTIONs, one fixed, two recorded:
- **Login-side clear gap (adversarial S1) - FIXED.** accountSignOut clears the
  per-device reserve keys on an EXPLICIT sign-out, but a session-expiry / crash-
  logout lands on /login without one. login.js now drops BOTH `ft-modern-avatarbar
  -count` (v1.99) and `ft-notif-bell-enabled` (v1.101) on a fresh login - the
  catch-all that stops user B inheriting user A's reserve on a shared browser.
- **Bell reveal is SOURCE-LOCKED not behaviourally bound (QA + adversarial) -
  tech-debt #139.** The account path is jsdom-behavioural; the bell is regex locks
  (a jsdom bell test needs localStorage + badge-poll setTimeout management, the
  #135 flake class). Behaviour verified correct today by the adversarial harness.
- **Bell placeholder doesn't anchor the queue insert (adversarial S2) - tech-debt
  #140.** A pre-existing cosmetic reshuffle the placeholder makes briefly visible;
  trivial one-line fix deferred.

## Adversarial attack surfaces (brief)
- Account/bell placeholder STRANDS (fetch reject / abort / signed-out), or
  DOUBLE-injects (re-entry, the async double-inject window), or the bell
  REVERSE-collapses undisclosed. The persist read/write is NaN/absent-safe and
  per-device (sign-out clears). Zero-shift: placeholder box == real control box.
  The mobile account hide applies to the placeholder too (not a phantom mobile row).
