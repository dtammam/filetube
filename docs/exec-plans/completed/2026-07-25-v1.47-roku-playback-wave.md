# v1.47 — Roku playback wave ("TV feature-complete")

**Status:** SHIPPED v1.47.0 (docs reset 2026-08-15; see ROADMAP.md). Was: ACTIVE (2026-07-25). Dean's brief: with these six, the channel is
feature-complete for his needs. All channel-side BrightScript — zero server
changes (`?format=` and per-item `chapters` already exist). Slim adversarial
gate; Dean's on-device pass is the arbiter. RBAC slides to v1.48.

## Decisions (Dean, at intake — all recommendations accepted)

1. **Filter:** Right on the grid cycles All → Video → Audio (`&format=`),
   persisted in the registry, shown in the header. `*` (options) is a
   same-action alias because the grid consumes Right except at a row's right
   edge (ArrayGrid boundary bubbling — same rule as the Left/libraries key);
   which key feels right is an on-device question.
2. **Playback menu on Down** (video or audio playing): one overlay listing
   Next: <title> / Previous: <title> / Chapters… / Loop: Off·This·All /
   Autoplay: On·Off / Restart from beginning. Chapters come from
   `GET /api/videos/:id` (lazy DetailsTask on first menu open per item; the
   list API doesn't carry chapters). Chapter pick → `video.seek`.
3. **Resume prompt** only on explicit selection with meaningful progress
   (>30s, <95%): "Resume from H:MM:SS" / "Start from beginning".
   Autoplay-advanced items keep today's silent auto-resume.
4. **Loop is 3-state**: Off / This (repeat current) / All (wrap the list).
   Loop + autoplay persist in the registry (all-lowercase keys).

## Architecture notes

- **Queue = the grid's own ContentNode.** GridScreen exposes `queue` (node) +
  `selectedIndex`; AppScene holds the same node the grid appends pages into,
  so infinite-scroll growth is visible to playback for free. An
  `ensureLoaded` (int, alwaysNotify) field lets AppScene prefetch the next
  page when playback nears the loaded tail (autoplay never starves; if the
  fetch loses the race, next simply stops at the loaded end — disclosed).
- Filter/search/library changes REBUILD the queue node → a stale index from
  a previous queue must never index into the new one (AppScene re-reads
  `selectedIndex` + `queue` together on each selection; menu prev/next
  clamps to the queue it captured at playback start).
- The Down-menu must not fight the native trickplay OSD: menu opens on
  `down` bubbling from the Video node (unused by the native UI), renders
  above the video (declared after it), and closes on Back (only — Down at
  the list's bottom edge is swallowed, not a close).
- Resume prompt uses the existing scene-dialog pattern; the playback gate
  ("Preparing…") runs AFTER the prompt so the answer applies to whichever
  bytes the server settles on.

## Deferred by Dean's own guardrail ("if it's a lot, don't break the flow")

**Channel browsing** (yt-dlp channel folders): `?folder=<folderName>` filtering
exists, but nothing LISTS the channels — the web UI derives rows from item
data. Doing it right = a small server endpoint (`/api/channels?root=` →
distinct folderNames from db.metadata) + a second level in the Libraries
picker. That reopens a server release cycle, so it heads the next wave
(v1.48, alongside RBAC) instead of riding this one.

## Out of scope

Server-side anything; music/books libraries on TV; PIN pairing; progress
write-back (still read-only). Tech-debt #50–#52 unchanged.
