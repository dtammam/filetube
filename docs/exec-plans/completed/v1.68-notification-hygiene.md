## Machine-derived facts (verified at main 0ba7db4 / v1.67.5; PREDICTIONS
## the tools re-verify at each commit)

- **P1 - feed shape.** `notifications` rows are GLOBAL: id AUTOINCREMENT,
  `media_id TEXT NOT NULL UNIQUE`, created_at (lib/db/sqlite.js:388).
  media_id UNIQUE means at most ONE row per media - the play-dismiss join
  key is unambiguous. Cap = `NOTIFICATION_CAP = 200`
  (lib/auth/store.js:264), overflow evicted oldest-first ON INSERT, "and
  its reads" evicted with it (:262) - dismissals must join that eviction.
- **P2 - per-user state today.** `user_notification_state` (seen + clear
  watermarks) + `user_notification_reads` (per-row dot). NO per-item
  dismiss lane exists. Routes: GET /badge, GET /, POST /seen, POST /read
  (400 on phantom id - the discipline the dismiss route copies), POST
  /clear (server.js:8010-8121).
- **P3 - schema.** `SCHEMA_VERSION = 7`, versioned `migrateSchema` with
  `if (current < N)` blocks (lib/db/sqlite.js:204) - a new table is a
  REAL v7 -> v8 bump, not an IF-NOT-EXISTS freebie.
- **P4 - backup.** `bundle.notifications = exportNotificationsForBackup()`
  (server.js:7563; validation ~7634; reads noted "absent in pre-v1.51
  bundles -- legal"). Dismissals join export + restore + validation with
  the same absent-is-legal posture, IN THE SAME COMMIT (v1.42 carrier
  law).
- **P5 - the play signal.** `POST /api/videos/:id/view` (server.js:12847)
  fires once per watch-page load - the play-START semantic, per-user
  (session-gated). The /history page reads `user_progress` (updated_at
  order); `user_watched` is the completed-threshold marker. The view ping
  is THE hook (ruling 1); the progress handler is deliberately NOT a
  second hook (one authority; a Roku-only gap, if real, is disclosed).
- **P6 - the SW banner.** `showNotification` (public/filetube-worker.js:94)
  sets NO tag; `data.url` carries the deep link, `/watch.html?v=<id>`
  since v1.67.4. So item 4 needs NO worker change: the PAGE can call
  `registration.getNotifications()` and close entries whose data.url
  matches the playing id. (A worker-side `tag` would also dedupe repeat
  banners - optional, weigh at implementation.)
- **P7 - fullscreen exits, coverage matrix at v1.67.5.** The scroll
  keeper (`setCssFullscreen` + `resolveCssFsScrollPlan`, player.js)
  covers: faux-FS captures on ANY entry (button or the
  webkitbeginfullscreen rotate-intercept at ~:4840) and restores ONLY on
  the exit-button call site. NOT covered: NATIVE fullscreen exits (the
  Done/X path in native-controls mode, and any native session on
  desktop-class mobile) - iOS notoriously clobbers page scroll on
  webkitExitFullscreen, and nothing restores it. Dean's rotate symptom
  was observed PRE-v1.67.5: in custom mode the rotate flow is
  rotate -> intercept -> faux-FS (captures) -> rotate back (faux
  persists) -> exit BUTTON -> v1.67.5 restores. **Probe-first: the
  symptom may already be fixed on his device by v1.67.5** - but the
  native-exit door is genuinely uncovered and gets closed regardless.

## Design decisions

- **D1 - dismissal storage.** New table `user_notification_dismissals`
  (user_id, notification_id, dismissed_at, PK(user_id,
  notification_id)), REFERENCES users ON DELETE CASCADE - the
  `user_notification_reads` shape exactly. Schema v8. Row eviction
  (P1) deletes matching dismissals in the same transaction. Reader
  changes: `listNotificationsForUser` and `countUnseenNotifications`
  exclude dismissed rows (badge and panel agree).
- **D2 - the dismiss verbs.** Store: `dismissNotification(userId, id,
  at)` (false on phantom -> the route 400s, the /read discipline) and
  `dismissNotificationByMedia(userId, mediaId, at)` (silent no-op when
  no row - a play is not an error). Route: POST
  /api/notifications/dismiss {id}. The play hook calls the ByMedia form
  inside POST /api/videos/:id/view after the view-count write succeeds.
- **D3 - panel UI.** An X per row (button, aria-label "Dismiss this
  notification"), single tap, NON-optimistic (v1.54 law: only confirmed
  answers REMOVE): POST -> success -> row leaves + badge refreshes;
  failure -> row stays, toast. Clear-all unchanged.
- **D4 - banner closing.** At the same client moment the view ping
  fires: `navigator.serviceWorker.getRegistration()` ->
  `reg.getNotifications()` -> close every notification whose
  `data.url` contains the playing id (URLSearchParams parse, not
  substring - id charsets are URL-safe but discipline is discipline).
  Feature-detected at every step; total silent no-op outside the PWA.
- **D5 - native-fullscreen scroll coverage (T5).** Extend the ONE
  keeper, never a second copy: capture on native ENTER
  (webkitbeginfullscreen / fullscreenchange-enter for the player's own
  elements, mobile form factor only, capture-if-not-already-held - the
  ON->ON rule so a native->faux handoff keeps the ORIGINAL capture),
  restore on native EXIT (webkitendfullscreen /
  fullscreenchange-exit), suppressed when the exit is the rotate
  intercept's programmatic handoff INTO faux (faux now on = not an
  exit, the capture carries forward). The faux paths are byte-unchanged
  from v1.67.5. Desktop fullscreen behavior untouched (mobile-only
  guard, disclosed).
- **D6 - the background-play investigation** happens AFTER this wave
  ships, as a findings report (docs/), no build commitment. Dean's
  anchor symptoms, verbatim spirit: (a) after locking or app-switching,
  video playback sometimes pauses a moment then resumes as audio,
  sometimes not; (b) Control Center play sometimes resumes it
  immediately, sometimes not; (c) audio-only is "mostly perfect" - the
  imperfection is VIDEO's background continuation.

## Gate brief - named attack surfaces (full gate: adversarial first,
## then QA, sequentially)

1. **Destroy the dismissal data's neighbors**: the eviction join (200-cap
   overflow) must never orphan or over-delete; restore of a pre-v1.68
   bundle (no dismissals key) must not wipe reads/state; a v1.68 bundle
   into a fresh instance lands dismissals intact. Backup/restore is the
   data-loss surface - full-gate rigor.
2. **Cross-user isolation** on every new verb (dismiss, ByMedia,
   readers).
3. **The migration**: v7 db opens, migrates once, reopens idempotently;
   a v8 db under old code (downgrade) - document the posture.
4. **Badge/panel coherence**: dismissed rows excluded from BOTH count
   and list; seen/read/clear interplay (dismiss an unread row - badge
   drops? clear-all then dismiss phantom - 400).
5. **The view-ping hook**: must not break the ping's existing contract
   (its suite is watch-view-ping.test.js); a dismiss failure must not
   500 the ping.
6. **T5 mutation surface**: the keeper's new native paths - the
   handoff suppression, capture-if-not-held, mobile-only guard - with
   exact-statement locks; prove the faux paths byte-unchanged.
7. **Banner closing**: must never throw outside the PWA; must never
   close a DIFFERENT video's banner (URLSearchParams, not substring).
