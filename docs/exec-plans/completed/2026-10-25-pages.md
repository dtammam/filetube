# Pages - save web pages and text, read them anywhere, share them with AI

Kickoff 2026-10-25 (Server/Web Root, Opus). **Builder: Smart (Opus).** New tables, a new on-disk store, untrusted
third-party HTML rendered in the app (XSS), a server that fetches user-supplied URLs and their images (SSRF), a new
credential kind, vendored third-party code, and a delete path. Additive (no migration of existing data), so not
Extreme. **The gate is FULL** (schema change + data-loss path + network boundary + third-party code:
`.harness/scrutiny.toml`): adversary + qa + security-brief.

Two releases on two branches, in this order:

- **R1 = v1.395.0** - capture, the Pages library and lists, Reader / Original, metadata + a note, full-text search,
  Share with AI, the iOS Shortcut, the Chromium extension, the extended Download dialog.
- **R2 = v1.396.0** - highlights and notes (separate plan, written after R1 ships; outline at the end).

## Why

Dean, 2026-10-25: "I want FileTube to be my one stop shop for consumable files." Articles people send him are read
sometimes, lost often. He wants each one captured in one tap from the share sheet (phone) or the browser (desktop),
kept forever as real files, readable in a clean view that keeps as much of the original as possible, with useful
metadata, and its text sendable to an AI with his own prompts, the way transcripts are today (Settings > Transcript
sharing). Self-hosted readers (Wallabag, Readeck) were weighed at intake and rejected: the point is one app, one
account system, Feed cards later, offline in the iOS app later, and the AI share.

ROADMAP "Feed phase 2: a Reading section (news as files)" is the RSS half of the same library. R1 builds the store and
the page; phase 2 later fills it from feeds and adds Feed cards. **No Feed cards in R1** (Dean: phase 2).

## Research (verified at kickoff)

- **Readability 0.6.0** (`registry.npmjs.org/@mozilla/readability/-/readability-0.6.0.tgz`, read 2026-10-25):
  `Readability.js` 2,786 lines (Apache-2.0), `JSDOMParser.js` 1,278 lines (MPL-2.0), `Readability-readerable.js`
  122 lines. **Zero `require(` calls, no `dependencies`.** Releases: 0.4.0 2020-12-23, 0.5.0 2023-12-15, 0.6.0
  2025-03-03. FileTube is MIT; Apache-2.0 is compatible; MPL-2.0 is file-level and stays in its own file with its
  header.
- **JSDOMParser needs well-formed HTML** (its own header, lines 10-19: "Properly formed HTML/XML must be used ...
  use XMLSerializer.serializeToString() ... and pass the resulting string"). Raw HTML from the web is often not
  well-formed. Hence D-PARSE: devices send `XMLSerializer` output; server-fetched HTML goes through our own tidier
  first.
- **Outbound fetch guard exists**: `lib/podcasts/fetchGuard.js` (on `lib/ytdlp/shortlink.js`'s `guardHop`:
  http(s) only, no userinfo, private/loopback reject, resolve-then-check failing closed, every redirect hop
  checked, byte and wall-clock caps, injectable transports). Reuse it for the page AND every image/stylesheet fetch.
  Its disclosed TOCTOU DNS-rebinding residual is inherited and stays disclosed.
- **Credentials**: `FILETUBE_API_TOKEN` is accepted ONLY on `POST /api/ytdlp/download` and leaves `req.user` unset
  (`lib/auth/gate.js:396-417`), so it cannot own a per-user save. Device tokens (`ftd_`, `lib/auth/devices.js`) are
  user-bound, hashed at rest, revocable, but `PLATFORMS = new Set(['ios'])` and paired by the iOS app. Hence D-AUTH.
- The Shortcut: iOS Shortcuts' "Run JavaScript on Web Page" action is available only when the Shortcut is run from
  Safari's share sheet; from any other app the Shortcut receives a URL or text. **The builder confirms this on
  Dean's phone through his device pass (it cannot be tested from the box)**; both paths are built either way.

## Design

### D-STORE - on-disk layout (source of truth for content)

```
<PAGES_ROOT>/<userId>/items/<yyyy>/<yyyy-mm-dd>-<slug>-<id>/
  item.json        metadata (P4) + note + source + schema version + content hashes
  reader.html      sanitized Reader HTML (absent when extraction failed)
  original.html    sanitized full-page snapshot (absent for text saves)
  text.txt         plain text of the Reader view (or the pasted text): search + AI share
  assets/          localized images, stylesheets, fonts (content-hashed names)
<PAGES_ROOT>/<userId>/trash/<same folder name>/   + a trashedAt stamp in item.json
```

- `<id>` is a short random id that is also the database key. `<slug>` is from the title, ASCII, bounded length.
  Every path is built from validated parts and checked to be under the user's folder (the `isConfinedUnderRoot`
  pattern, `lib/podcasts/index.js:208`).
- Writes are atomic: build the folder as `.<name>.part`, fsync, rename. A crash never leaves a half item that the
  rebuild would index.
- A note edit rewrites `item.json` atomically (temp + rename).
- Caps (constants, documented): page HTML 10 MB, total assets 50 MB per item, 300 assets per item, pasted text 2 MB,
  per-fetch wall-clock deadline. Over a cap: drop the extra assets (logged on the item), never fail the save.

### D-DB - the index (rebuildable)

New tables (schema bump in `lib/db/sqlite.js`, the only module allowed to `require('node:sqlite')`):
`pages_items` (id, user_id, folder, url, canonical_url, title, site, author, published_at, saved_at, word_count,
lead_image, has_reader, has_original, read_at, position, trashed_at), `pages_lists`, `pages_list_items`
(list, item, order), and an FTS5 table `pages_fts` (title, site, author, note, body).
- **Rebuild**: a scan of `<PAGES_ROOT>` re-creates `pages_items` + `pages_fts` from `item.json` + `text.txt`
  (on boot when the table is empty, and from Settings > Scan & cache). Read state, position and lists live only in
  the database and are **included in the admin backup** (`lib/admin/backup.js`).
- Every query is scoped by `user_id` server-side; there is no unscoped read path.

### D-PARSE - turning HTML into Reader + Original

`lib/pages/` (new). Pipeline for a URL save:
1. **Input**: device HTML (from `XMLSerializer`, with the page URL) or server-fetched raw HTML (via the fetch
   guard).
2. **Tidy** (server-fetched only, ours: `lib/pages/tidy.js`): a tolerant tag-soup tokenizer/tree builder in vanilla
   JS that emits well-formed markup: void elements, implied closes (`p`, `li`, `td`, `tr`, `option`, ...), raw-text
   elements (`script`, `style`, `textarea`, `title`), entities, unclosed tags at EOF, comments, CDATA, doctype.
   Not a full HTML5 parser; the bar is "Readability gets a sane tree" on the fixture corpus.
3. **Parse + extract**: vendored `JSDOMParser` + `Readability` (D-VENDOR) with the page URL so relative links and
   images become absolute. Metadata: Readability's `title`, `byline`, `siteName`, `excerpt`, `publishedTime`,
   `lang`, filled in by ours from `og:*`, `article:*`, `twitter:*`, `<link rel=canonical>`, and JSON-LD
   `Article`/`NewsArticle` when missing.
4. **Sanitize** (ours: `lib/pages/sanitize.js`): a strict **allowlist** of tags and attributes for Reader; a
   broader allowlist for Original (keeps layout tags, `class`, `style`, `id`). Always removed: `script`, `noscript`
   content handling, `iframe`, `object`, `embed`, `form` controls, `base`, `meta http-equiv`, every `on*`
   attribute, `javascript:`/`data:` (except image data URIs) / `vbscript:` URLs, `srcdoc`, `formaction`. CSS:
   `@import` and any `url()` not pointing at a localized asset are removed; `expression()` and `behavior` removed.
5. **Localize assets**: images (`src`, the best `srcset` candidate, `<picture>` sources, lazy-load attributes such
   as `data-src`), stylesheets (Original only, inlined after sanitizing), fonts (best effort, under the cap). All
   fetched through the fetch guard, stored content-hashed in `assets/`, references rewritten. A failed asset is
   dropped, never fatal.
6. **Write** D-STORE, then index D-DB.

A text save skips 2-5: the text is stored as `text.txt`, Reader is that text rendered as escaped paragraphs.

### D-RENDER - showing untrusted HTML safely

- **Reader** renders inline in the app (needed for R2 highlights), from `reader.html` that has already passed the
  Reader allowlist, inserted under a container that the app's own CSS styles (font, size, width, the Books
  paper / sepia / night themes and settings reused). Links open in a new tab with `rel="noopener noreferrer"`.
- **Original** renders in `<iframe sandbox="allow-popups allow-popups-to-escape-sandbox">` (no `allow-scripts`,
  no `allow-same-origin`), loaded from `GET /api/pages/:id/original` which is served with
  `Content-Security-Policy: default-src 'none'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; font-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'self'`
  and `X-Content-Type-Options: nosniff`. Assets are served by `GET /api/pages/:id/assets/:name` with a strict name
  pattern, the stored content type, and the same CSP. Defense in depth: the sanitizer AND the sandbox AND the CSP.

### D-AUTH - saving from a Shortcut

- A new device-token platform **`shortcut`** (add-only in `PLATFORMS`), minted from **Settings > Pages > Set up the
  iOS Shortcut** by a signed-in user (password re-entry, as device pairing does), shown once with a copy button,
  listed and revocable with the user's other devices.
- **A `shortcut` token is accepted ONLY on `POST /api/pages` (save).** Any other route with a `shortcut` token is
  401. (An iOS device token keeps today's scope and may also save.)
- `FILETUBE_API_TOKEN` is **not** accepted by Pages (it has no user).

### D-API

All under `/api/pages`, all user-scoped, JSON, the existing body-size and error conventions:
- `POST /api/pages` - save. Body: `{ url?, html?, text?, title?, note?, source }`. Exactly one of: `url` alone
  (server fetch), `url` + `html` (device capture), `text` (+ optional `url` / `title`). Returns the item, or the
  existing one with `duplicate: true` (P12). Saving is asynchronous past the first response if asset fetching runs
  long: the item appears at once with a "saving images" state and completes in the background; a failure there
  leaves the text item intact.
- `GET /api/pages?view=all|unread|trash&list=<id>&q=<search>&cursor=` - the library.
- `GET /api/pages/:id` (metadata + reader HTML), `GET /api/pages/:id/original`, `GET /api/pages/:id/assets/:name`,
  `GET /api/pages/:id/share?promptId=` (the P8 text).
- `PATCH /api/pages/:id` - note, read state, position. `DELETE /api/pages/:id` - to trash.
  `POST /api/pages/:id/restore`. Lists: `GET/POST /api/pages/lists`, `PATCH/DELETE /api/pages/lists/:id`,
  `PUT /api/pages/lists/:id/items` (membership + order), `GET /api/pages/lists/:id/share?promptId=`.

### D-UI (mobile and desktop are both first-class)

- **Pages page**: views All / Unread / each list / Trash; a search box (full text); an **Add** button (paste a URL or
  text, plus an optional note); cards with lead image, site, title, author, saved date, reading time, unread dot.
- **Item page**: metadata header (title, author, site with the original URL, published, saved, reading time), the
  note (tap to edit), the **Reader / Original** toggle, Add to list, Share with AI, Mark read, Delete. Reader
  settings reuse the Books themes and text size. Resume position.
- **Download dialog**: a Video / Audio / Page choice; with yt-dlp off, the dialog (and its button) still exists
  with Page only.
- **Chromium extension** (`extension/`): a "Save to Pages" action beside the download; it serializes the active
  tab's document (`XMLSerializer`) and posts it with the URL, falling back to the URL alone where the page cannot
  be read. Any new manifest permission is the minimum (`activeTab` + `scripting`) and is listed in the release
  notes.
- **Settings**: "Transcript sharing" becomes **"Share with AI"** (same prompts, P8). A new **Pages** section: the
  Shortcut setup (token + step-by-step instructions for both Shortcut paths) and the trash period note.
- Every new control follows the measurement norms (rows wrap, buttons never shrink; probe before/after) and the
  existing looks (`docs/LESSONS.md` UI sections).

### D-VENDOR - the vendoring rule (written into `docs/ARCHITECTURE.md` in R1)

Third-party code enters FileTube only when ALL hold: it is a core capability we could not reasonably write and
maintain ourselves at the same quality; it is plain JavaScript with **no dependencies of its own**; it is stable
(slow release cadence, long track record); its license is compatible. It is **copied into the repo**, never
installed from npm: `lib/<area>/vendor/` holding the unmodified files, a `README.md` (source URL, version, date,
license, sha256 of each file, the update procedure), and a test that fails if a vendored file's sha256 drifts from
the README (no silent edits; local changes live in our wrapper). This is an exception, not the norm; the default
remains: write it ourselves.

R1 vendors `Readability.js`, `JSDOMParser.js` and `Readability-readerable.js` from 0.6.0 into `lib/pages/vendor/`.

### Error handling

A save never loses what it got: fetch failed with device HTML present = use the device HTML; extraction failed =
Original only; assets failed = the item without them; a server fetch that fails entirely with no HTML = the error is
shown and nothing is written (the user still has the link). A Shortcut save that fails returns a plain message the
Shortcut can show.

### Testing strategy

- Fixture corpus `test/fixtures/pages/`: about 15 real pages saved as raw HTML (news, blog, Substack-style
  newsletter, docs, a long-form essay, a page with tables and code, one malformed tag-soup page, one non-article
  page, one with lazy-loaded images, one non-English). Each with expected title, author, published date, a word-count
  range and key sentences present in Reader text. Run through BOTH paths (raw + tidy, and browser-serialized form).
- Sanitizer: a hostile-input suite (`<script>`, `on*`, `javascript:`, `srcdoc`, SVG with script, CSS
  `url(javascript:)`, `@import`, mixed-case and entity-encoded variants, `<base>`, `<meta refresh>`); mutation:
  remove each rule, watch its test go red (LESSONS: presence-not-binding).
- SSRF: every asset URL goes through the guard (a private-IP image URL, a redirect to loopback, a `file:` URL).
- Isolation: user A cannot read, search, share, list-add or delete user B's item by id (every route).
- Data: rebuild from files after dropping the tables restores every item + note; a crash mid-write leaves no
  indexed partial; delete -> trash -> restore round-trips byte-identical; trash expiry removes only trashed items
  older than 30 days.
- Auth: a `shortcut` token saves and is 401 on every other route; revocation ends it.
- Vendored hash test.
- UI: Pages page and item page on phone and desktop widths, both views, the Download dialog with yt-dlp on and off.

## Deviations

No ruling (P1-P14) or acceptance line changed. Implementation choices the design did not spell out, each with its reason:

1. **D-DB: read state and position are not columns of `pages_items`.** They live in `pages_state` (user, item id), and lists
   name items by id value (no FK to the index), so an index rebuild (boot, Settings, a restore) can never forget what was
   read or listed. A users-replacing restore re-inserts them from the bundle's per-user `pages`, then rebuilds the index from
   the files.
2. **D-PARSE: every input is tidied, device HTML included.** A device is a client we do not control, and the vendored
   JSDOMParser fails on anything not well-formed; measured on the corpus, raw + tidy and the XMLSerializer form give identical
   results.
3. **D-RENDER: the Original inlines its own stored images and fonts as `data:` URIs in the response** (the assets route stays,
   for the Reader and the lead image). Measured (tools/pages/sandbox-cookie-probe.js): Chromium and Firefox send no
   SameSite=Lax cookie for a sandboxed frame's image requests, so `assets/` URLs would 401 there; WebKit sends it. The CSP
   allows `img-src`/`font-src` `'self' data:` and adds the CSP `sandbox` directive. The sandbox and auth are unchanged.
4. **D-STORE: `owner.json` per user folder; a deleted account's folder is set aside** (`.deleted-users/`, renamed, never
   unlinked). A users-replacing restore inserts the bundle's ids, so an id can come back as a different person: a rebuild
   indexes a folder only for the account whose name its owner.json names, and a save by a different account sets the old
   folder aside before it writes its own owner.json (gate r1 A1 / W1).
5. **An item's URL is `/pages?id=<id>`**: the SPA router matches exact paths only, so `/pages/<id>` would full-reload.
6. **The extension uses the same save-only `shortcut` token kind**, minted under its own name ("Browser extension",
   Settings > Pages): its existing `FILETUBE_API_TOKEN` belongs to no user and cannot own a save (D-AUTH).
7. **Download dialog:** a native host without the `mediaFetch` capability (the App Store build, v1.391.0) still shows no
   Download surface at all; Page-only applies to a browser with yt-dlp off. There the button arrives with the module probe
   (no pre-paint reserve, which means "the module is on").
8. **Settings > Scan & cache > Rebuild Pages** calls a new admin route `POST /api/pages/rebuild` (D-DB names the Settings
   entry; the route was implied).
10. **Gate r1 fix round:** the capture's CPU work (tidy, Readability, both sanitize passes) runs in a worker thread with a
   20 s deadline (lib/pages/process.js): a slow Reader saves Original-only, a page that cannot even be tidied in time is
   refused (422) with nothing written. The fetch guard checks the connect-time DNS answer (`checkedLookup`, closing the
   rebinding window for the podcasts too). The Reader is sanitized again when served. A save-only token's duplicate gets
   `{ duplicate, message }` only. The Settings token buttons read "Make Shortcut token" / "Make extension token".
   Gate r3 round (Dean chose to run it): captures share a bounded queue (2 processing, 4 waiting, then a 503 with a
   message), both web save toasts show the server's message, and a folder is set aside only on positive evidence it is
   someone else's.
9. **Fixture corpus:** 12 pages from Mozilla Readability's own test corpus (their expected metadata is the independent
   oracle) + 3 live captures under open licenses; no Substack page is redistributable, so `medium-1` (a hosted newsletter
   platform) stands in for that kind (test/fixtures/pages/README.md).
